# Riftwarden: project notes for future sessions

Browser FPS + tower-defense roguelite. Current milestone: **M10** (biomes with factions, ground hazards, enemy mutations, faction archetypes) on top of **M9** (procedural arenas: seeded 170-200 m sectors with districts, nav-grid pathing with tower mazing + breaching, forward rifts, loading screens), M8 and the fast-pace pass (see "Key design decisions"). Read this before changing code.

## Stack

- **Babylon.js 8** (`@babylonjs/core`) for rendering, picking, particles, post-processing.
- **Havok** (`@babylonjs/havok`, Babylon Physics v2) for the static level collider, the player's `PhysicsCharacterController`, and line-of-sight raycasts.
- **React 18** for HUD and menus (`src/ui`), fed by a tiny external store.
- **Vite 7 + TypeScript (strict)**, **Vitest** for unit tests.
- **M7 co-op server**: Node + `ws` + `tsx` (`server/`), runs the real `Game` headless (Babylon `NullEngine` + Havok wasm).

Use engine features before writing custom systems (user direction): collision, picking, raycasts and particles come from Babylon/Havok.

## Conventions (architecture rules)

- **`noImplicitOverride` is on**: a method that overrides `Game` (ServerGame/ClientGame) must say `override`, so renaming a base method breaks loudly.
- **Lint is a ratchet** (`npm run lint`, also in CI): errors for real bugs (`any`, awaiting non-promises, hook rules); warnings for floating promises and size (`max-lines` 800, `max-lines-per-function` 250). Do not add to the warning list; new files stay below the limits.
- **Extract by narrow interface, not by passing `Game`**: new arena systems take a small host interface (see `DevTools`/`DevHost`) so they are testable and do not grow the god object. `Game.ts` is still the biggest hotspot (see "Refactoring backlog").
- **Behaviours**: every enemy archetype is a `Behavior` registered by `Game` (`CORE_BEHAVIORS`, `M6_BEHAVIORS`, ...). `EnemyManager` is pool + routing + damage resolution only, and must not import a behaviour module (cycle).
- **Replicated presentation**: add a call to the lists in `net/replicated.ts` (compile-checked against the real classes) instead of new string literals on either side.
- **Rules before effects**: decision logic (what is rolled, what a refit costs, who a blast hits, which hint shows) lives in pure functions with injected randomness/ids/line-of-sight; `Game` only applies the result. New logic of that kind goes in a pure module with an equivalence/property test, not into `Game`.
- **Typed wire events**: every server-emitted tuple tag is in `net/events.ts` and handled in `ClientGame.applyEvent`; `tests/net-events.test.ts` greps the emitters and the handler so neither side can drift, and the e2e asserts the client rejected nothing.
- **No milestone names in APIs**: name by intent (`nextTowerCost`, `shaderWarmup`, `towerHud`). The HUD snapshot keys `m5`/`m6` are legacy store shape.
- **Architecture tests** (`tests/architecture.test.ts`) enforce the boundaries above (acyclic `progression/save`, no behaviour imports in `EnemyManager`, no `Game` value import in `src/arena`, pure modules free of Babylon values); `tests/save-surface.test.ts` pins the save barrel's exports. Extend them when adding a boundary.
- **e2e scripts import `scripts/lib/harness.cjs`**; do not copy launch/boot helpers again. Restart `vite` if you delete/rename files while it runs (it caches module resolution and the page then never boots).

## Key design decisions

### Destruction + VFX pass (after M10)

- **Mechanical fragmentation** (`fx/Fragments.ts`, choice in `fx/fragmentPlan.ts` [pure]): when a robot bursts, `fx.shatter(root, centre, power, max, heat)` throws its own largest visible solid parts (same kit template, so a walker's shin really flies) as pooled GPU instances per template: thrown outward + up, spun, bounced off the floor/level boxes (`CollisionBoxes`), glowing hot through the hit-flash buffer (cools orange -> red), smoke-trailing while hot (the debris trail picks from them), shrinking out after 2.6-4.2 s. Capped (72 high / 44 low x density; the oldest piece is recycled). Skips unlit/transparent parts, greebles < 8 cm and hulls > 4.5 m. Called from `EnemyManager.kill`'s burst (generic debris is thinned when pieces flew), the crawler death and both boss finales.
- **Explosion styles** (`fx/explosionStyles.ts` [pure]): `ExplosionOpts.style` = fire (default) / plasma (violet energy ball, no fire) / electric (arcs + delayed crackle bursts) / cryo (frost cloud + ice shards, no fire, no scorch) / heavy (two delayed cook-offs, burning wreckage via `Smolder.linger`, more debris and shake). Death styles per kind in `deathAnims.ts` `BLAST` + `deathStyle` (frostbound -> cryo, molten/volatile/detonated -> heavy). Styles replicate (the style string rides in the `explode` options).
- **Damage states** (`fx/Smolder.ts`, thresholds in `fx/wounds.ts` [pure]): below 55% HP a machine trails dark smoke, below 35% it spits sparks, below 20% it burns. `EnemyManager.update` and `Turret.update` call `fx.wound(pos, r, severity)` per frame (sources sit on the upper body: emitted inside a rig they are hidden by it); three particle systems for everything, whose emitter hops between the sources frame by frame. Wrecked towers burn until repaired.
- **Particle rendering gotchas (found in this pass, SwiftShader)**: (1) systems positioned only through `startPositionFunction` rendered nothing in testing, while emitter-positioned systems did; the Smolder systems therefore move their emitter instead (the older Effects debris/plasma trails and `BounceSparks` still use `startPositionFunction`: suspected invisible, now at least anchor their emitter on a live source; not verified). (2) Plain `BLENDMODE_STANDARD` smoke did not show; standard-blend smoke must go through `softenParticles` with the sprite sheet, as Effects' smoke does (that shader linearises colour, so greys come out dark). Additive systems render with the default shader.
- **Hit reaction** (`enemies/hitReact.ts` [pure]): every non-DoT hit kicks a damped spring that leans the enemy root away from the source (local pitch/roll from the hit direction and the damage share); bosses, burrowers and pylons are excluded (their rigs pose the root). Replicas kick from the local warden on `ed`.
- **Shield break** (`fx.shieldBreak`): shard burst + plasma + hard ring + flash light. **Tower assembly** (`towers/assembly.ts` [pure]): pedestal prints up from the deck with weld sparks, the head drops onto its bearing with an overshoot while spinning into alignment, the core lights with a ground ring; same `buildTime`. **Muzzle heat** (`fx/MuzzleHeat.ts`): smoke wisps off a hot barrel between shots, a steam jet while locked out.
- **Co-op**: `shatter` and `wound` are no-ops on the server (recorder); the client's puppet fx lets `burst`, `wound` and `shatter` through (presentation of replicated kills/HP).
- **Regression**: npm test 375, e2e-polish A-C 16/16, e2e-m5 24/24 (J stress avg 5.0 / p95 25.9 ms vs 5.2 / 24.3 ms on the pre-pass commit on the same machine: no measurable cost; this machine is slower than when the 1.9 ms figure was recorded). Co-op protocol suite not run (needs `RIFT_TEST_DATABASE_URL`).
- **Validation**: `tests/destruction.test.ts`; `node scripts/vfx-shots.cjs [A|C|D]` captures wounds, fragmentation, the five styles and tower assembly. Particles only age while rendering: step `advance(1/60)` + `render(1)` together when capturing effects.
- **Not done yet**: screen-space heat distortion for shockwaves; environmental props are not destructible (rubble is static dressing); HQ structures have no damage states (nothing damages them).


### M10: biomes, factions, hazards, mutations, faction archetypes

- **Biomes** (`world/biomes.ts`): `biomeForSeed(arenaSeed)` splits sectors evenly between the outpost, the cryo excavation and the molten foundry; `layout.biome` (absent on the classic arena = outpost). Look: `scene.fogDensity`, sun colour/intensity and the palette tint (`tintPalette`) are set by editing existing constructor lines in place (the Game constructor is at its 250-line limit: keep it there); fog colour goes through `moodInput().baseFog` (`moodFor` starts from it); `Atmosphere` reads the biome for the sky horizon, air particles (ash / falling snow / rising embers, rate multiplier) and rain (outpost only); lane lights use `biome.lane`. Sector names use the biome's word pool.
- **Factions**: `SurvivalPlanner(seed, tier, faction)`; Game passes `biomeOf(layout).faction` only when `layout.biome` is set, so the classic arena keeps its exact roster. `factionMix` multiplies theme weights (`bias`) and adds signature archetypes (`extra`, relative to the mix's average weight); `rollMods(kind, n, rand, {wave, weights})` gates mutations by `MUTATION_WAVE` and weights them (a 0 weight never rolls: Molten never appears in cryo, Frostbound never in the foundry); `eliteRate` scales the elite chance. Rime (cryo): bulwarks/enforcers + burrowers, Frostbound. Crucible (foundry): rushers/artillery + skimmer swarms + marksmen, Molten/Volatile/Splitting. Scrapline (outpost): sappers + marksmen.
- **Hazards** (`arena/Hazards.ts`): generator plants 7-11 patches (r 3.5-7 m) in open walkable ground away from the plaza, drop point and rifts, reserved for construction. Frost: the drone below 2.6 m moves at x0.65 (`Player.update` speed multiplier), ground enemies gain chill (towers then freeze them). Slag: 12 dps to a low drone, ground enemies ignite (Molten immune). Molten mutants drop transient slag (5 s). Co-op: the server runs `decay` + `affectEnemyList` once and `affectPlayer` per avatar (`as(a, ...)`); transient patches replicate as `['hz', x, z, r, kind, life]` (protocol v7); replicas set `affectEnemies = false` and only slow their own drone.
- **Mutations** (`survival/elites.ts` defs + `enemies/mutations.ts` runtime, called from `EnemyManager.updateElite`/`kill`): regenerating (4%/s after 2 s without HP loss, not while burning), splitting (two copies at 40% HP via `ctx.summon`; small frames only, excludes volatile), shielded (+45% max HP barrier, excludes armored), blinking (7 m along the path every ~4 s, not while shocked/frozen), frostbound (chill immune in `Director.inflict`, telegraphed 6.5 m frost nova shorting towers), molten (burn immune, slag trail via `ctx.hazard`). Hardware per mutation in `eliteParts.ts` (unlit materials cached per scene; threat pips for all ten modifiers). Prebuild attaches every modifier's hardware to a walker so shaders warm up.
- **Archetypes** (`enemies/factionBehaviors.ts`): Sapper (walker rig + charge pack; leaves its lane for a tower in sight within 18 m, plants a 2 s fuse, detonates: 460 x dmg to the tower via `ctx.damageTower` -> `TowerWear.breach`, suppression blast; shock/freeze holds the fuse; at the reactor it detonates there), Skimmer (small rusher rig; swoops at the drone within 24 m, pecks 6, peels away, repeats; rams the reactor), Marksman (walker rig + rail barrel; paints the drone with a thickening red laser for 1.6 s, 34 damage, cancelled by 0.35 s without LOS or by shock/freeze), Burrower (crawler rig x0.72; travels buried on the terrain field (`PASS_TOWERS`), `Enemy.hidden` = untargetable + unhittable (`EnemyManager.damage` returns null, towers skip it, hitboxes unpickable), surfaces every ~5.5 s for 3.2 s to fire bolts, and for good within 11 m of its path end to drill the reactor; buried state derives from the replicated `ai.mode`).
- **Regression after M10**: npm test 366, e2e-m10 24/24, e2e-arenas 16/16, coop protocol 47/47 (classic and `RIFT_ARENA=procedural`), m5 24/24, m1 69/70 (known Z). e2e-m6 B,C: B6 (engineer holds back), B7 (courier escape) and C4 (volatile, only when run after B) fail **identically on the pre-M9 commit d5265a3** (fast-pace pass speeds), C1 is timing-flaky under CPU load (passes on reruns, C alone 7/7).
- **Tests**: `tests/m10.test.ts` (biome split, hazards placement/reservation, faction mix, archetype completeness, faction compositions + determinism, mutation exclusions, wave gating, faction weights); `node scripts/e2e-m10.cjs` 24/24.
- **Not done yet**: biome-specific structure dressing (ice/foundry props) and skyline; burrower wake is a particle puff only; hazards affect only the drone and ground enemies (not towers); mutations are not shown on the co-op team HUD; balance is first-pass.

### M9: procedural arenas, mazing, loading screens

- **One layout per run.** `ArenaConfig.layout` (default: the classic `ARENA`); `Game.layout` is a getter on it and every arena system (builder, dressing, floor, atmosphere, dynamics, placement, effects, radar, dev tools, server/client) reads it. Solo: `Flow.arenaSeedFor(runId)` = `hash(run id) ^ 0x2545f491` (independent of the upgrade/planner seed), `flow.nextArenaSeed` forces one. Co-op: `CoopSim.arenaSeed` -> `RunStart.arena` (protocol v6); both sides call the memoised pure `generateArena(seed)`. `arena: 0` / `flow.arenaMode = 'classic'` = hand-built arena. **`?test` defaults to classic** (legacy suites measure its geometry; `?test&procedural` opts in); test servers too unless `RIFT_ARENA=procedural`.
- **Generator** (`world/arenaGen.ts`): half 84-100 m, gates stay at the wall midpoints (shared `perimeterBoxes`/`southDoorBox`, so gate frames, mist, lights, tunnels and dressing line up). Keep-outs: reactor plaza (19 m), drop point, gate mouths. Order: districts (below), 4-7 platforms (h 3-5) with one ramp (x or z axis), 7-12 blocks, 10-19 pillars, 4-8 wall machines (south wall along x, east/west along z: the builder dresses those faces), rejection-sampled with 4.2 m walkable gaps. Lanes (`routes`) are traced on the terrain-only nav grid, vents sit halfway along them, 2 forward rifts per gate sector 34-62 m out. Reserved: bulkheads, gate mouths, rift pads, vents. Tests: `tests/arena-gen.test.ts` (determinism, size, reachability of gates/rifts/spawn, lanes off solids, plaza clear, re-plan speed).
- **Districts** (`world/districts.ts`, staged in `arenaGen`: `districtStage`, `scatterStage`, `skywayStage`): new `SolidKind`s `barrier` (0.9 m concrete walls, 3.2 m: the drone vaults them with jump + boost), `container` (2.6 m per level, top is a `platform` surface) and `bridge` (deck whose underside is at h - 0.45: the nav grid ignores it, its pylons block). Each gate gets an **inner district inside a bastion ring** (a rectangle of barrier walls whose sides meet at the corners, 22% chance of a 4.5 m breach per long segment), so every ground lane passes through a maze, a serpentine chicane, a staggered container yard or under an overpass (staggered baffles at both mouths); then an **outer winged district** (wings 30-48 m, 35% chance of a tip gap) further out, plus off-lane redoubts, yards, a second maze, platforms, blocks, pillars, machines and up to 4 **skyways** (bridges between facing platforms of equal height). Overlap tests are per box for multi-part pieces (bounding rects of winged pieces overlap everywhere). Connectivity safety net: while a gate cannot reach the reactor, the latest piece on its approach is dropped. `layout.features` lists the set pieces (briefing chips). Average lane length is >1.1x the straight line (test). Visuals in `ArenaBuilder.buildBarrier/buildContainer/buildBridge` (railings have thin colliders). Towers standing above 1 m (decks, bridges, container tops) never block the ground field and are never breached.
- **Navigation** (`world/navgrid.ts`): 1 m cells over the arena + tunnels, solids inflated by 1.5 m (perimeter, boxes, bulkheads, ramps). Towers add cost (45 per metre) instead of blocking, so a sealed maze still yields a path through the cheapest tower. One Dijkstra from the reactor ring (radius 7) per change (~30 ms at 200 m); `pathFrom` descends the field and string-pulls with segments that avoid solids **and** tower cells. `version` bumps on every change.
- **Enemies** (`enemies/navigation.ts`, plugged in as `EnemyManager.nav`, null on the classic arena and on co-op replicas): ground kinds use the tower-aware field, flyers (`FLYERS`: rusher, jammer, artillery, courier, overseer, pylon) the terrain field. Spawns: 55% from one of the gate's forward rifts (bosses/HVTs always through the gate), path from the spawn point; `Enemy.gate` keeps the lane identity (server `laneOf`). Per frame (real time) `sync()` re-reads tower footprints every 0.25 s (`bumpStats` syncs at once); an enemy whose `navV` differs re-plans from its position. `follow()` asks `nav.blocked(e, next)`: a live tower ahead stops the walker, which hits it every `max(0.7, attackInterval)` s for `(8 + reactorDamage x 4) x damageMult` (bosses x4). Summons set `navV = -1` to re-plan from the summon point.
- **Tower durability** (`towers/durability.ts`, `arena/TowerWear.ts`): standard 420 / bastion 720 / spire 330 HP, +25%/level, x sqrt(wave damage mult) (rescaled at build and on wave clear, keeping the HP fraction). 0 HP = **wreck**: no firing, no blocking (nav re-plans), slumped/dark rig. Repair (F, same phase rule as refits; `act repair` in co-op) costs 40% of paid x missing fraction (wreck x1.25); wreck recycle refunds 40% of the normal refund; intact towers mend 25% on every wave clear. HUD: structure bar + repair cost in the inspect panel; radar greys wrecks. Snapshot tower rows carry hp/max/wrecked (indices 8-10).
- **Placement on mazing arenas** skips the lane rule (`blocks-route`); reserved zones still apply.
- **Scale fixes**: floor/collider span and tunnel caps follow `half`; outside industry, masts and quarry rocks scale by `max(1, (half+30)/74)` (rocks capped at 1.35 to stay inside the camera-following 300 m sky dome); sconces and pipelines run the full wall length; radar range = half + 13 with rift rings.
- **Loading screen** (`ui/LoadingScreen.tsx`): `Flow.transition(title, sub, build, info)` publishes `transit {kind, stage, sector}`: stage 0 charting -> 1 building (painted before the synchronous build) -> 2 compiling shaders -> 3 ready. Arena kind shows the sector card (code, name, tier, span/structures/plateaus/rifts/gates) and an SVG map of the generated layout (structures by kind, ramps, animated lanes, pulsing rifts, reactor, drop point, radar sweep); HQ/visit kinds show recovery art. Tips rotate every 4.2 s. Real deployments hold the briefing for at least 1.4 s (not with `forceCapture`). Animations are transform/opacity (compositor) so they keep moving while the scene build blocks the main thread. `__rift.previewLoading(seed, stage)` shows it without loading (screenshots).
- **Testing notes**: `node scripts/e2e-arenas.cjs` 16/16; co-op protocol 47/47 on both arenas (`RIFT_ARENA=procedural`; the test bot speaks protocol v6); m1 69/70 (known Z), m5 24/24. SwiftShader compiles shaders asynchronously: let the page idle between renders before screenshots of new viewpoints (synchronous `render(n)` loops show only unlit materials).
- **Not done yet**: player-built wall pieces; lane lights show the unobstructed route (not the live maze path); biome palettes/factions (M10); chunked culling/LOD for the larger arena (measure on a real GPU first); co-op clients do not show breach sparks between snapshots.

### HQ + terminal pass (after the fast-pace pass)

- **Comparison model** (`loot/loadoutScore.ts`): `loadoutScore(items)` -> dps (weaponSummary with equipped stats), ehp ((hull + shield) / (1 - mitigation) at wave 1), mobility and tower indices (100 = stock). `swapImpact(equipped, candidate, replaced)` -> per-headline deltas + verdict (only gains = upgrade, only losses = downgrade, mixed: weighted score >= 3% / <= -3%, else sidegrade). Every list that shows items next to the loadout uses it (storage/arena inventory, market stock, engineering previews of equipped items).
- **InventoryView**: hover previews an item side by side (detail + ComparePanel with the impact banner) without changing the selection; actions only render for the selected item. Search (`matchesQuery`), "upgrades only", "best first" sort, arrow keys + Enter (equip), ignored while typing.
- **Terminal styling** lives at the end of `style.css` ("terminal redesign"): accent per terminal via `--acc`, verdict colours `--up/--down/--side`.
- **HQ surfaces**: `HomeBase` builds deck/wall/ceiling materials from `hqTextures` (ORM + emissive). The arena palette is unchanged. Rooms get accent lighting from `roomStyle` (floor perimeter line, corner columns with slits and colliders except in the command deck, cove strips, cable tray with hangers) and tinted room lights; accent materials are one merged mesh each.
- **Tests**: `tests/loadout-score.test.ts`. Regression after the pass: npm test 342, e2e-m4 39/39, construction G-J 30/30, polish D-E 6/6, progression 18/18, m2 52/54 (C8/C9 fail identically on the pre-pass commit).
- **Hard-surface geometry**: `loftData` turns every rectangular section (n >= 3) into a chamfered octagon (`chamferRatio(n)`: 7-24% of the shorter half-extent) with creased facet columns; along the loft, quads share normals only below a 22 deg bend. Round sections (n < 3, `smoothLatheData`) keep the smooth superellipse path. Kit boxes chamfer 0.035 (was 0.08, which stretched into fat rounded edges when scaled), the enemy soft box is a crisp n=6 chamfered block, HqBuilder boxes default to min(0.035, 12%). Test: `tests/sculpt.test.ts`. Regression: e2e-m3 37/37, polish A-B 13/13.
- **Weathering**: `wearSet(scene, high, rust)` adds rust runs (vertically stretched noise, pitted, lower metal/higher roughness): 1 in the arena, 0.3 in the HQ; every material using the wear albedo (graphite, enamel, enemies) shows it. Outdoor `wallSet` warms its runoff and bleeds rust below rivets; `yardDeckSet` has oil stains, rust stains near joints and canvas-drawn cracks. New palette materials `rust` (`rustSet`: oxide with flaking paint) and `debris` (dark concrete, wear normal only; rubble chunks carry vertex colours, so the arena's `rubbleConcrete` merge group must hold only rubble). Rubble is visual only (no colliders, not pickable) and merged per material (+2 draw calls: debris, rust). HQ: three scrap heaps in reclamation (`HqBuilder.add` is public for them). Tests: `tests/rubble-plan.test.ts`. Regression: e2e-m1 69/70 (the known Z hit-flash compile error; a dedicated HQ + arena + kill load shows no shader errors).
- **Art direction pass** (critique from wide free-camera tours, not close-ups): arena = rift-scarred industrial outpost at storm dusk. Sky: slate zenith, warm dust near the sun, heavier dark clouds, ridges darkened/warmed by sun angle (`rwSky`); `BASE_FOG` [0.3,0.29,0.3], density 0.0042; storm fill 0.26 (cool), sun 1.85 warmer; arena grade contrast 1.22 / exposure 1.08 (`Game`, one line: the constructor is at the 250-line limit). Outdoor palette: concrete [0.4,0.4,0.39] (was cream), panel [0.5,0.52,0.52], white [0.5,0.5,0.48] (clean paint, wear only in ORM), rust amount 0.6; deck oil/rust stains 2-4 m (period 36/40). Skyline quarry rocks are dark cool basalt (`scannedProps`), pushed out x1.35 and lowered. Boss fog mixes to [0.3,0.09,0.08] (polish C2 needs a > 0.1 luminance drop). HQ: graphite deck [0.34,0.36,0.38] with light clear coat, walls [0.6,0.62,0.64], dark ceiling [0.2,0.21,0.23] with one light slot per 2.5 m tile (emissive 2.2), terrazzo [0.3,0.3,0.29], no deck grates, hemi 0.3, contrast 1.16. Tour script pattern: teleport, advance, then set `player.camera.position` + `setTarget` and render (views inside solids show their interior faces: pick viewpoints outside boxes). Regression: npm test 341, polish A-E 21/21, construction G-J 30/30, m1 69/70 (known Z).
- **Second art pass**: viewmodel `ANCHOR` moved down/right (x 0.19, y -0.172, z 0.46, yaw -0.085, pitch 0.015) so the receiver's rear cap leaves the frame; `arctic` shell is worn satin [0.64,0.65,0.63] (was cream), weapon micro texture has grime + stronger scratches (normal 0.45). Partition cheeks use the weathered outdoor `panel`. Build pads (`planPads` in `world/rubblePlan.ts`, rendered by `ArenaFloor.pad`): dark squares with orange corner brackets beside every lane bend, tested clear of lanes/solids/reserved; rubble avoids them. HQ command deck inlay (`HqBuilder.commandInlay`: bronze rings, accent ring and light lines to the three doorways); wall texture seams are faint so the wall-run frames carry the structure. Regression: npm test 342, e2e-m3 37/37.
- **Third pass (weapons, textures, atmosphere)**: weapon micro texture carries machined panel seams (`SEAMS_U`, plus one long seam) with fasteners, so every large shell reads as panels (UVs tile per 0.5 m of weapon); beam shell cheeks use n 3.4 (hard-surface) instead of smooth capsules. Wear texture: weak speckle and brushing (dense dark pits and fine vertical brushing read as cork / wood grain under warm light); outdoor wall runoff streaks ~20 cm. Outdoor `graphite` is painted steel ([0.12,0.135,0.145], metallic 0.22) so the low sun does not turn it tan; new `steel` (blackened, wear only in ORM) on gate tunnel slabs and tunnel dressing. Regression: npm test 342, polish 21/21, m1 69/70 (known Z), m3 37/37 (I2 arc check is chance-based: failed once, passed on two reruns).
- **Weapon handling pass**: every shot applies `shotFeel`: pitch kick (def `recoilPitch`) plus a patterned sideways kick (`Player.recoilYaw`, `yawPattern`: ~68% right), a lens punch (`Player.punch`: FOV narrows / roll, layered on top of the smoothed FOV via `appliedPunch` so it never moves the crosshair, decays at 18/s, off with reduced motion), shake for rail/scatter/cycle. Regression: npm test 345, m3 37/37, m5 24/24, polish A-C 16/16, m1 69/70 (known Z).

### Fast-pace pass (after M8)

Goal: high-tempo play (think VOIDBREAKER): fast enemies, little dead time, momentum movement, punchy kills. Measured with
`scripts/playtest.cjs` (bot, tier I, towers): waves 1-8 clear in 20-35 s each with first contact ~2.5-4 s after the call-in
(before: 24-43 s for fewer enemies, 18-30 s prep in between).

- **Tempo** (`waves/pace.ts`): prep 20 s (wave 1) / 12 s, clear celebration 1.6 s, every spawn time x0.72 (hand waves and
  the planner). Calling a wave early (G) pays `2 cores` per whole skipped second (`earlyCallBonus`, alert "EARLY CALL"),
  on top of Rapid Deployment. The upgrade picker keeps the pointer lock: 1/2/3 picks and play resumes at once (Esc frees
  the cursor; clicking a card re-locks inside the gesture).
- **Enemies** ~1.6x faster (`ENEMIES[*].speed`: walker 5.8, rusher 14, bulwark 4.5, ...). Walkers/Bulwarks shoot the drone
  more often (2.0 / 1.8 s, 0.48 s telegraph, bolts 28 / 31 m/s); reactor attack cadence is unchanged. `WalkerMotion`
  shortens the swing and lengthens the stride with ground speed so feet stay planted.
- **Movement** (`Player.MOVE`): run 16.5, sprint 24, dash 50 -> carry 31, gravity 30. Momentum: above the run/sprint
  target and pushing roughly along the velocity, speed bleeds at `overspeedDecel` (26 m/s^2 ground) / `airDrag` (6 m/s^2)
  while steering toward the input, so dash -> jump -> boost chains keep ~30 m/s; releasing the keys still stops in ~0.1 s.
  A grounded dash drops the eye (`slideDip`), carried overspeed widens the FOV (`speedFov`) and adds aberration +
  vignette (`PostFx.speed`, `Game.motionFx`, both off with reduced motion); a dash start kicks the lens. Server
  `MAX_SPEED` = `MOVE.dashSpeed + 4`.
- **Kill feel** (`Game.playerKill`, direct weapon kills): hitstop dilates *hostile* time only (0.045 s x0.2, heavy kills
  0.1 s x0.04; `hitstopEnabled = false` on the co-op server), dash refund (`killDashRefund` 0.3, heavy x2; replicas refund
  on their personal `hit:kill` event), kill chain per Player (`chain`/`chainAt`, 2.5 s window) -> personal `chain` UI event
  -> `KillChain` HUD (x n CHAIN / RAMPAGE 6+ / OVERDRIVE 12+), kill sound pitch rises with the chain.
- **Deaths**: `DEATH_TIME` ~0.4-0.7 s; the kill pops immediately (sparks, debris, small flash) and the wreck is knocked
  away from the last hit's source (`Enemy.hitFromX/Z`, `wreckKnock`, drag 5/s, clamped to the arena). The final burst
  re-reads the wreck position. Ordinary explosions use one star flash at 0.75x size (pairs only from scale >= 1.5) so
  pack fights stay readable.
- **Numbers**: `DamageNumberEvent.target` (enemy id x4096 + spawn gen) merges hits on one target within 0.45 s into one
  rising total that pops per hit and keeps the strongest kind.
- **Heat** (`combat/heat.ts`): heat x0.75, cooling x1.35, cool delay x0.7, full-rate cooling while locked out (was 75%).
  Applied at fire time so existing items get it; `weaponSummary` uses it so terminals show effective heat/cooling.
- **Smoothness**: `Flow.frame` feeds `FrameClock` (steady deltas replace jitter within 20%, debt repaid proportionally,
  1/20 s clamp). Beam endpoint computation is allocation-free.
- **Not done yet**: real-GPU feel check; a dedicated slide key (C is taken by tower refits, Ctrl+W closes tabs); kill
  feel for tower/effect kills; hitstop is not replicated to co-op clients; balance of faster waves on tiers IV-V is untested.

### M8: Warden progression

- **XP is derived, not collected.** `xpFor(ledger)` (waves cleared with a slow per-wave growth, kills, elites, bosses, events, HVTs, milestones) x tier factor (+25%/tier) x `ledger.xpMult` (keystones). `RunLedger.accrueXp()` moves the delta since the last call into `unsecured.xp`; `bank()` and `finalize()` accrue first, so XP follows the salvage rules: banked at checkpoints (`bankRewards` adds `rewards.xp` to `save.progress.xp`), on defeat/abandon `XP.keepOnLoss` (25%) of the unsecured XP is kept (`result.xpKept`, applied by `recordRun`), extraction keeps all. Dev sessions earn 0. Co-op: `ServerGame.bankAll` calls `syncStats()` + `a.run.accrueXp()` before cloning each player's ledger; replicas mirror `xs/xu` from `ledgerView` and set `xpReplica` (never derive locally).

### M7: co-op, HQ construction, content, presentation

- **Co-op architecture.** The server runs the *same* `Game` code (`ServerGame extends Game`) in Node: `server/headless.ts` stubs the browser, Babylon `NullEngine`, Havok loaded from wasm. Presentation is captured by the `Recorder` (fx/wfx/telegraph/ordnance/sfx/uiEvents are monkeypatched) and streamed as event tuples (`ev`), with per-player routing (`to`/`not`). Snapshots (20 Hz) carry wave/reactor/cores/tactical, enemy rows + deltas of AI primitives, avatars, towers, ordnance, boss/survival HUD, checkpoint/vote/offer state and a personal block (`me`: ledger view, inventory when dirty).
- **Replica.** `ClientGame extends Game` never simulates hostiles: enemies are spawned from `es` events and their behaviour code runs only as an animation driver through a puppet context; positions are interpolated 100 ms behind (`Track`). Shots are resolved locally for feedback and sent as **claims** (`ShotClaim`: family, origin, dir, power, heat, hits [netId, weak, point]); the server checks family, fire-rate budget, origin vs its eye (3.5 m), range, reach around the enemy (latency allowance), LOS (Havok), then computes damage itself from the server-side loadout. Rejections are counted per reason (`ServerGame.why`, logged on test servers). All other intents are `act` messages with replies (place/recycle/modify towers, tactical, startWave, collect, upgrade, vote, equip/unequip/discard, `test` only with `RIFT_TEST=1`).
- **Shared vs personal.** Shared: reactor, towers (any player refits/recycles; refunds to the shared cores), cores, tactical energy (anyone toggles), waves. Personal: equipment, run cargo, loot (drops are rolled per player with their own RNG and only visible/collectable by the owner), ledgers. `TeamLedger` mirrors shared resource rewards into each player's ledger; each player banks at checkpoints into their own online profile (`bankRewards`, guarded per player). Team upgrades: the chooser rotates between players, 30 s auto-pick. Checkpoint vote: unanimous among connected players to return; 45 s timeout = continue. Team defeat ends the run for everyone; unsecured rewards are lost per player.

Online profiles start fresh. HQ mutations are named ops (`progression/ops.ts`) executed by the same code on both sides: `Profile.op` runs locally in single player and is forwarded (`op` message, tx id) when online (`attachRemote`/`adoptRemote`). Ops are refused while the profile is in a run. The server commits deployment, checkpoint awards, and run results before publishing the saved state.
- **Reliability.** Protocol version check on `hello`; `parseClientMsg` validates every message structurally (malformed traffic and token-bucket rate limits close the socket after 50 strikes); max 64 KiB per message. Disconnect: the slot (and unsecured rewards) is held 120 s, a reconnect with the same identity rejoins the running operation (`runStart` with `rejoin`). Host transfer on leave/disconnect. Duplicate sign-in replaces the older socket.

The guest returns automatically when the session ends or they become host.

Stations can be relocated (`base.stations`). Removal refunds in full so undo/redo is value-neutral. Blueprints: starter, merchant (bought at the architect console), milestone/tier/boss unlocks derived from persisted records, fabrication (machinery). Facilities: storage annex (+10 bays), market uplink (+market progress), calibrator. Everything costs secured HQ resources, so unsecured run rewards cannot bypass banking.

- **Save v7**: `base.structure/stations/blueprints/owned`, `tutorial`; `MIGRATIONS[6]` marks the tutorial complete for existing players. Signatures are validated and backfilled (`rollSignature`).

### M5: roguelite upgrades, elements, modular towers

- **One damage pipeline.** Every source (weapon, tower, status tick, effect, reaction) calls `Director.deal()`: vulnerability (chilled +, frozen +25%) -> elemental power -> `EnemyManager.damage` -> attribution (`damageBy`, per-tower kills/damage) -> reactions + statuses -> kill handling (`Game.onEnemyKilled`) -> typed events. `Game.damageEnemy` is the legacy entry (rolls crit, plays hitmarkers) and routes to it.
- **Effect bus** (`events.ts`): effects register under an owner id (`upgrade:<id>`) and are rebuilt from scratch on every pick (no duplicate listeners). Events carry `chain {id, depth}` and `source {kind,id,towerId}`. Rules: damage is never dropped, only trigger propagation: events deeper than `MAX_DEPTH` (4) reach no effects; an effect fires at most `chainLimit` (default 1) times per chain; cooldown + chance per effect; queue drained per frame with budget 300 (carry-over) and hard cap 1500 (refusals counted in `stats.dropped`). Pooled enemies carry `gen`; events compare it so recycled targets are ignored. Visual work (arcs, heavy explosions, numbers) has per-frame budgets; logic does not.
- **Statuses** (`status.ts`, stored on `Enemy.status`, reset on spawn/release): Burning (stacks to 5, 0.5 s ticks), Shocked (0.5 s disruption, 2 s internal cooldown), Chilled meter (slow up to 55%, freeze at 100 for 1.5 s then 5 s immunity). Statuses also scale enemy movement, attack timers and animation. Reactions use the contact element (hit element or applied status), consume their fuel and have per-target cooldowns: thermal shock (thermal on chill>=50), overload (electric on burning), superconduct (electric on chill>=40, +2 chain). DoT ticks never react.
- **Run upgrades** (`upgrades.ts`): live only in `Game.director.build` (never in the save; a new `Game` = empty build). Stat upgrades are StatModifiers per stack (`RunBuild.modifiers()`), others are bus effects keyed by upgrade id in `effectsFor`. `Game.rebuildStats()` composes equipment + debug + upgrades + temporary buffs (event driven). Offers: `RunBuild.roll(ctx, index)` seeded by (seed, index) -> deterministic; rarity weights x depth, tag affinity, stack penalty, eligibility (`needs`: towers, notFamily, anyTag, towerArch; `minWave`), max one legendary, category diversity. Flow: wave cleared -> prep start -> `openUpgrade()` (screen `upgrade`, sim and prep countdown frozen) -> `chooseUpgrade` -> checkpoint panel if due -> resume. Seed: `ArenaConfig.seed` (`flow.nextUpgradeSeed` for tests) else hash of run id. `skipUpgrades` (Flow/Game) is automation-only (legacy suites).
- **Modular towers** (`towers/components.ts`): `TowerConfig {base, weapon, core, modifier}`, archetypes ballistic / arc / cryo field. `composeTower` is the single source of numbers (base x weapon x core x modifier x level x run stats x empowerment), recomposed lazily when `statsVersion` changes. Default config == the old Sentinel (cost 100). Compatibility is explicit (`canInstall`). Refit (`Game.modifyTower`): weapon/core/modifier swap (net cost = new - 50% old, x `buildCostMult`) or level up (max 5); allowed in prep/cleared, and in combat only while tactical mode is active; base is fixed. Hotkeys: aim at tower + R/C/V/N (build mode: C/V/N/M cycle the template); T opens the panel (prep only); U shows the run build.
- **Synergies** are bus effects (Phase Sync empowers towers on Storm Crit lightning; Thermal Detonation; Cryogenic Precision in `damageEnemy`; Feedback Loop / Battle Network Link buffs on tower kills; Overcharge Network, Conductor Link, Grid Capacitor discharges). Tower attribution travels in `source.towerId`.
- **Persistence**: save v5 adds `towers.unlocked` (`slot:id`; starters implicit). `economy/transactions.researchTower` (HQ only, best wave + credits/components, tx id guard); UI = workshop "TOWER TECH" tab. `ArenaConfig.towerTech` snapshots unlocks at deploy. Deployed towers, levels and run upgrades are never persisted.
- **Diagnostics**: F3 shows FPS, enemies, towers, projectiles, bus queue, effects, triggers/s, statuses, dropped triggers, player/tower dps.
- **Tests**: `tests/m5.test.ts` (bus, statuses, reactions, upgrades, towers, research/migration); `node scripts/e2e-m5.cjs` (24 checks: upgrade flow, seeds, reset, statuses/reactions, tower refit incl. tactical, synergy, 42-enemy stress with 19 upgrades, research reload). Legacy e2e scripts set `flow.skipUpgrades`.
- **Limitations / not done**: no protective-barrier upgrade, no combat-drone legendary; towers are not damageable (base "durability" is not modelled); Cryogenic Field is not occluded by walls; element visuals reuse pooled bursts (zap/frost added); balance is first-pass; real-GPU FPS not measured (headless SwiftShader sim: 1.9 ms avg/frame, p95 12.7 ms with 42 enemies, 6 towers, 19 upgrades).

### M4: persistent economy, merchants, salvage, fabrication, engineering

- **Three resources** in `save.resources`: `credits`, `salvage`, `components` (advanced components). Run income (`RUN_INCOME`): wave clear credits, checkpoint credits + components (tier-scaled), credits per kill (elites most), 25% elite component chance. They go through `RunLedger` (unsecured -> banked at checkpoints -> lost on defeat) exactly like salvage; `bankRewards` applies them. New profiles and v3 migrations get `STARTING_CREDITS` (200).
- **One formula file** (`economy/config.ts`). Everything grows linearly with `levelFactor(L) = 1 + 0.1(L-1)` (levels are clamped, counters capped, results rounded non-negative integers): no unbounded exponentials. Item value = 18 × levelFactor × rarity value × category × affix quality; buy = value × 2.3-2.4, sell = value × 0.3, enhancement never adds value. Unit tests assert buy→sell/dismantle and craft→sell/dismantle are always lossy at exchange prices (`EXCHANGE_UNIT`), and that material conversions are lossy both ways.
- **Transactions** (`economy/transactions.ts`): every action validates everything first (HQ only, ownership incl. modules installed in owned weapons, protection, eligibility, cost, storage bay) then mutates synchronously; failures return `{ok:false, reason}` with the save untouched. `withTx` remembers the last 40 committed tx ids (repeat submissions rejected). UI goes through `useTx` -> `Profile.transact`, which restores the pre-transaction state if a rule fails and **rolls back if the storage write fails** (so success is only reported once persisted; `profile.failWrites` test hook). Batch dismantle/sell are all-or-nothing.
- **Protection**: equipped items, installed modules and `item.locked` items cannot be sold or dismantled. Selling/dismantling a weapon returns its modules to storage. Presets referencing a removed item are cleared.
- **Merchants**: `save.market` holds the stock (8 equipment, 6 modules, featured slot = rare floor, max epic), generated by `generateItem` at `progressLevel` (best cleared wave + that tier's loot bonus) from `marketSeed(profile, rotation)`. Reopening never rerolls; `recordRun`/interrupted runs rotate it; paid refresh escalates per rotation. Stock items are full `ItemInstance`s (sanitized on load; an entry whose uid is already owned is forced sold). Exchange packs are limited per rotation and cannot be sold back.
- **Affix engineering** (`economy/engineering.ts`): single 'stat' reroll (any compatible affix from the same pool/weights, group uniqueness kept), 'value' refine (same affix, new tier+roll), full reroll of unlocked affixes. Tiers use the generator's `rollTier` + rarity minTopTier guarantee; values use `rollAffix` (level scaling, quality floor, affixMult). Randomness = `engineeringRand(uid, seed, rerolls)`: deterministic, so restoring a backup cannot fish. Locks are per affix (`affix.locked`), max affixes-1, each lock adds salvage + components to a full reroll. Costs escalate +15%/op (`item.rerolls`, capped ×10). Item names and `signature` never change.
- **Enhancement**: `item.enhance` 0..`MAX_ENHANCE[rarity]` (4/6/8/10/12/15). Applied in the stat pipeline only (`itemModifiers`, `weaponDefFor`; stored rolls untouched): weapons +4% damage +1.5% cooling per level, gear +4% to beneficial implicits, modules +5% to all beneficial stats (penalties never amplified, counts like projectiles never scaled). Never fails.
- **Component engineering**: barrel/core/cooling/mechanism swaps limited to `componentsFor(slot, family, rarity)` (prism core stays legendary+; a railgun can only get rail mechanisms). Because effects are baked into rolls, the roll is rescaled by new/old `buildEffects` ratios (quality preserved). The model builder reads the build, so preview/viewmodel update automatically.
- **Fabrication** (`economy/recipes.ts`): recipe (category, weapon family or module base) × quality grade (standard C-U, refined U-R +1 comp, superior R-E needs tier II, masterwork E-L needs tier III with luck 0.5 → ~10% legendary). Output = `generateItem` at `progressLevel`, source 'crafted', seed from `economy.crafts` counter. Exotics are never craftable; merchants cap at epic.
- **HQ**: two new rooms from layout data (`market` east of storage, `reclaim` west of the drone bay; portals at x=±23/-21; sealed doors moved to the far walls), 4 new stations (`merchant`, `modules`, `salvage`, `fabricate`). Live displays: exchange wall bays mirror stock rarity/sold state, broker vault cores + exchange tanks, press hopper fill (log of salvage) and component cells. `uiEvents 'econ'` triggers `HomeBase.stationFx` (press stroke, fabricator glow, vault spin, calibration ring, sounds) and HUD resource deltas. Interior materials take 10 lights.
- **Save v4**: `MIGRATIONS[3]` adds credits/components; sanitize generates the market/economy if missing and validates item engineering fields (`locked`, `enhance` capped by rarity, `rerolls`, `mods`, `affix.locked` with at least one affix unlocked).

### M3: weapon families, procedural weapons, modules, engineering

- **Families** (`data/defs.ts` templates, `weapons/build.ts` FAMILIES): Plasma Repeater (hitscan + travelling bolt visuals, `auto`/`burst`), Railgun (`charge`: hold to charge, release fires 30..100% damage, partial charge = less heat; or `cycle`: automatic full slugs; slugs pierce `pierce` extra enemies at -15% each), Beam Emitter (`beam`: 15 damage ticks/s, damage ramps to `rampMax` while the beam stays on the same enemy, `beamWidth` aim-assist radius, shorter range). All damage still goes through `Game.shoot` -> `damageEnemy` -> `rollDamage` -> `EnemyManager.damage`.
- **Bases are chassis**: 3 per family (`plasma_repeater/heavy/light`, `rail_lancer/siege/striker`, `beam_prism/lattice/focus`). `generateItem` rolls the base numbers, then `rollBuild` (own seeded stream: `seed ^ 0x5bd1e995`) picks barrel, core, cooling, mechanism, 0-3 attachments (by rarity), finish (legendary = gilded, exotic = iridescent) and appearance params; component multipliers (`buildEffects`) are **baked into the stored `WeaponRoll`** (+ `range/accuracy/pierce/chargeTime/beamWidth/rampMax`). Only components offered for the family (and rarity: prism core = legendary+) can roll, and every one has geometry for that family, so no invalid combination exists. `GENERATOR_VERSION = 2`.
- **Stat composition** (`loot/equipment.ts`): `weaponDefFor` = family template -> stored roll -> build mechanism. Everything else is StatModifiers in `CombatStats` (affixes, installed modules, other gear, run modifiers), applied at fire time: damage × weaponDamageMult × thermal (1 + heatDamage × heat), rate × fireRateMult, heat / heatEfficiency, spread/recoil × spreadMult, charge/ramp × chargeRateMult, range × rangeMult, projectiles (floor), pierce (+). New stat keys: `projectiles, spreadMult, chargeRateMult, arcChance, arcDamage, heatDamage, pierce, rangeMult` (only modules/components produce them).
- **Sockets**: weapons only; count per rarity in `rarity.ts` (0/1/2/3/4/4); kinds (`barrel`/`power`/`system`) follow a per-family pattern and are stored in `build.sockets`. Module types (8 + 3 legacy M2 inserts) each fit one socket kind and a family list (splitter = plasma only). `canInstall` is the single rule.
- **Ownership**: installed modules live **inside** the weapon item (`socketed: (ItemInstance|null)[]`), not in `items`/storage, so a module can never be in two places and always shares the weapon's carried/secured/unsecured status. `itemModifiers(weapon)` includes its modules (exactly once); loose modules contribute nothing. `allOwnedUids` covers nested uids (banking duplicate guard).
- **Engineering transactions** (`save.ts`): `installModule` (free), `uninstallModule` (salvage = `removalCost`, needs a free storage bay), `transferModule` (same cost, no bay needed). HQ only (`activeRun` blocks), owned weapons only (equipped or stored), validate everything before mutating. Scrapping a weapon returns its modules to storage.
- **Save v3**: `MIGRATIONS[2]` sets M3 socket counts (weapons) / 0 (others) and drops the old `modules` uid list; `sanitizeItem` validates builds (invalid -> `defaultBuild(chassis)`: stats untouched), validates nested modules against their socket (incompatible ones are evicted to storage, never deleted) and de-duplicates uids across nesting. M2 module bases stay (weight 0) and install into barrel/system/power sockets.
- **Viewmodel**: `buildWeaponModel` builds per-family chassis that expose mount points (barrel axis/z, core bay, top, flank, sockets); components attach to those mounts, so parts never float. Static parts merge per (animated node, material) => ~25-35 meshes per weapon. Animated hooks: slide (recoil), spinners (coils, rings, prism core), fins (open with heat), charge nodes (rail capacitors/rings), 5 heat LEDs (material swap), per-model energy/charge/heat materials. A drone hardpoint arm (viewmodel only) runs off-screen. The animator is spring based and dt driven (deterministic under `advance()`).
- **First person**: anchored at `Weapon.ts` `ANCHOR`; x/y offsets and scale are multiplied by `tan(fov/2)/tan(ref/2)` so the weapon keeps its screen footprint under FOV changes (sprint kick, settings). Shots are resolved from the camera ray (crosshair accurate); visuals start at the muzzle and end at the resolved hit point.
- **Effects** (`WeaponFx`): streak quads are rotated around their axis to face the camera (crossed quads vanish when viewed along their length). Plasma bolts have a tail toward the muzzle and run their impact effect on arrival; rail trails fade/widen; the beam is one persistent ribbon pair + endpoint flare + light; arcs are 6 jagged segments. Impacts differ per target (surface, shield, armour) and family.
- **Preview**: `WeaponPreview` uses a second small `Engine` on its own canvas because the terminal overlay blurs the main canvas; it captures a studio env once, rebuilds the model only when uid/build/installed modules change, and disposes engine+scene on terminal close (`window.__preview` while open, for tests). Debug: `__rift.lab(items, opts)` renders models in front of the camera for visual QA.

### M2: loot, equipment and inventory

- **Definitions vs instances.** `bases.ts` + `affixes.ts` + `rarity.ts` are data; `generateItem(spec)` turns a (seed, base/category, level, rarity) into an `ItemInstance` that stores *every* rolled number (implicit stats, affixes with tier/roll, weapon roll, sockets, seed, generator version). Loading never rerolls; formula changes only affect new drops. Same seed + spec + `GENERATOR_VERSION` reproduces an item.
- **Every stat is real.** Affixes and implicits only target `CombatStats` keys that a system reads (weapon damage/rate/crit/heat/cooling, hull, armor, resist, shield cap/regen/delay, move, dash recharge, turret dmg/rate/range, Sentinel cost, tactical recharge). `STAT_DEFS` holds base, clamps, labels. Stacking: `(base + Σadd) × (1 + Σpct) × Π(1+mul)`, then clamp.
- **Single pipeline.** `equipment.ts` turns the equipped items into modifiers and the weapon item into a `WeaponDef`; `Game.refreshEquipment()` rebuilds stats from scratch on every equipment change (never per frame), so swapping/unequipping cannot leave bonuses behind. Player gets hull/shield/mitigation via `Player.applyStats`; armor is measured against `flatScale(wave + tier bonus)` so its value tracks enemy level.
- **Scaling.** Flat values grow with `flatScale(L) = 1 + 0.08(L-1) + 0.0009(L-1)²`; percentages with `pctScale` (log2); chances/delays do not scale (stat clamps bound them). Affix tiers unlock with level (`maxTierFor`). Item level = wave + tier `lootLevelBonus` (0/8/18) + source bonus + (-1..+2). Rarity luck = source × tier `lootLuck` × (1 + 1.2%/wave), capped (`MAX_LUCK`). `MAX_ITEM_LEVEL` (1e6) is a numeric safety bound only.
- **Rarity** sets affix count, roll floor (`quality`), tier bias, guaranteed top tier, base multiplier, future sockets, colours and beam height. Ranges overlap so rolls and tiers matter as much as rarity. Legendary/exotic have no signature effects yet (`signature: null` is reserved in the save shape).
- **Drop tables** (`drops.ts`): walker 8.5%, rusher 5%, bulwark (elite) 55% + uncommon floor + exclusive Bulwark Plating (target farming), wave clear 40% (guaranteed on wave 1), checkpoint cache 2× rare+ (granted *with* banking), boss (data only). Category weights per source.
- **Physical loot** (`LootField`): instanced hologram per category icon, rarity ground ring, halo (epic+), additive beam (uncommon+), landing pulse/flash/chime for rare+, banner for legendary+. Loot shaders are force-compiled at arena build and awaited by the transition. Lifetime (`lifetime.ts`): dropped in wave W → expires when W+2 is cleared; evaluated only on wave clears (pauses/inspection never age loot). Saturation: at 40 pickups, sub-rare drops become salvage at drop time (never deleted after appearing); rare+ always spawn (hard guard 120).
- **Interaction**: `pickInteractable` (same as HQ) over landed pickups within 3.4 m + Havok occlusion; E collects into the run cargo. Prompt shows rarity/category/level and a quick level comparison; nearby pickups get projected name tags (imperative DOM pool).
- **Ownership is decided by the ledger, not slots** (`RunInventory`): `carried` (equipped at deploy, never lost), `secured` (banked this run, in the save), `unsecured` (cargo, cap 20). The arena gets *clones* of the equipped items; arena equip/unequip/discard only touch the run loadout and are allowed only in the `prep` phase (`Game.equipAllowed`). At run end `Flow.endRun` records the run and then `applyLoadout(save, inventory.ownedLoadout())`: slots holding lost items are skipped, so the profile keeps its previous secured gear.
- **Banking** reuses M1: kills/pickups → `RunLedger.collect` (idempotent by uid) → `bank(wave)` → `bankRewards` validates every item (`sanitizeItem`) then applies in one step; guarded by `bankedThroughWave`. The checkpoint UI says "secured" only if the write succeeded (`Profile.lastWriteOk`). Banking never drops items: storage may exceed capacity, which blocks deployment until the player scraps items or buys an expansion.
- **HQ**: storage terminal = shared `InventoryView` (filter by category, sort rarity/level/newest/name, detail, raw comparison + "drone stats if equipped" via the real stat pipeline, equip/unequip, scrap for salvage, +10 bays for salvage = first salvage sink). Drone configuration = slots, calculated stats, 3 saved presets (references into owned items; missing items skipped). Workshop became weapon engineering in M3 (see above).
- **Modules** are `category: 'module'` items with `module {type, compatible, socketCost}` and at least one affix; `itemModifiers` returns nothing for them and the UI states they are inactive.
- **Save v2**: `MIGRATIONS[1]` drops the unused `module` slot, adds `presets` and `storage.expansions`; `sanitizeItem` upgrades M1 items to the deterministic level-1 common roll (same 13 damage repeater), keeps unknown-base items (inert, unequippable), validates every number. Capacity = 50 + 10 × expansions.

### M1: sessions, scenes and persistence

- **One world at a time.** `Flow` owns the engine loop, the single `Input` (window listeners are registered once), the `Profile` and either a `HomeBase` or a `Game`. `Flow.transition()` paints the transit overlay, disposes the old Babylon scene completely (`scene.dispose()`: meshes, materials, textures, physics world, post-processes, observers), builds the next, waits (bounded 8 s) for `whenReadyAsync` while rendering but not simulating, then reveals it. A new run is always a new `Game`, so towers, enemies, waves, effects and wallet can never leak between runs. Pointer lock lives on the shared canvas and survives the swap (request it inside the click gesture, before any await).
- **Never `clone()` a palette material** (it clones DynamicTextures, which come out blank and never report ready; that stalled readiness for 8 s on every transition). Build fresh `PBRMaterial`s instead.
- **Run lifecycle.** HQ deploy → `beginRun` (save.activeRun) → arena. Kills and wave clears `collect` salvage into `RunLedger.unsecured`. Every 5th cleared wave the ledger `bank()`s and `Flow` commits it with `bankRewards` (guarded by `activeRun.bankedThroughWave`, so repeated hooks cannot duplicate). The following prep phase opens the checkpoint choice (`Game.checkpointOpen`; H reopens it until combat starts). `returnHome` / defeat / pause-abandon → `RunLedger.finalize()` (idempotent; unsecured becomes lost) → `recordRun` (idempotent by run id) → HQ. A save that still has `activeRun` on load was closed mid-run and is recorded once as `interrupted`.
- **Save format** (`riftwarden.save` in localStorage): `{"v":1,"sum":"<fnv1a of data json>","data":SaveData}`. SaveData = profile, resources.salvage, items[] (every owned item; each uid is in exactly one of loadout/storage), storage{capacity,uids}, loadout{weapon,armor,shield,reactor,processor,module,accessory}, threat{selected,unlocked}, records{tier:{bestWave(cleared),bestKills,runs,checkpoints,salvageSecured,longestRun}}, totals, history (last 12), activeRun, base{layoutVersion, placeables[], facilities[]}. Load: checksum/parse failure → raw text kept in `riftwarden.save.corrupt`, previous good save restored from `riftwarden.save.bak` (rotated on every write) or defaults. Newer versions are refused, older ones go through `MIGRATIONS[n]`. `sanitizeSave` repairs everything else (never deletes owned items, re-equips a weapon if needed). Writes happen only on committed rule changes (deploy, bank, run end, tier select, equip), never per frame.
- **Rewards in M1** are salvage only (persistent resource, no sink yet; the workshop says so). Items are modelled end to end (ledger, banking into storage, equip-from-storage for functional slots) but nothing drops them until M2; tests use fixture items. Only the weapon slot is functional; other slots are defined and shown as empty.
- **Threat tiers** (`tiers.ts`) multiply wave hp/damage/speed/count via `getWave(n, scaling)`; salvage scales by `salvageMult`. Tier N+1 unlocks at the first checkpoint on tier N. Records are per tier.
- **HQ customisation foundation.** Static architecture is code (`layout.ts` + `HqBuilder`); everything a player will later move/add is a `Placeable {uid,type,position,rotationY,scale,props}` in `save.base.placeables`, rebuilt by `buildPlaceable` on every visit (sanitised: unknown types dropped, positions clamped to `PLACEABLE_BOUNDS`).
- **Interaction.** `pickInteractable` picks the station focus point closest to view centre inside a cone (widens up close) and range (`INTERACT_RANGE`, per-station override), rejecting points occluded by a Havok `ENV_QUERY` ray that stops 0.4 m short (the focus sits on the station's own collider). E opens a terminal (screen `terminal`, pointer released); E/Esc closes (Esc cannot re-lock the pointer in browsers, so it falls back to the pause overlay).
- **Canvas textures on planes** go through `props.planeBuilder` (faces local +z, V flipped for DynamicTexture). Unlit materials have zero reflectance (`metallicF0Factor = 0`) so SSR never paints over screens/glows.

### M0

- **Two clocks.** `update(dt)` uses real time for player, weapon, turrets, UI; `hdt = dt * tactical.hostileScale` for enemies, enemy projectiles and spawn timing. Tactical mode only dilates hostiles.
- **Lanes are reserved.** Enemies follow fixed polylines (`ARENA.routes`) with per-enemy lateral offset; placement forbids towers within `laneHalfWidth + radius` of a lane on the floor, so construction can never block navigation. A 5 s stuck watchdog snaps enemies to their waypoint.
- **Hit detection.** Player hitscan uses `scene.multiPickWithRay` against meshes tagged `metadata.surface` (level) or `metadata.enemy` (invisible hitbox spheres: body + weakpoint). Turret hitboxes (`metadata.turret`) are only used for inspection, shots pass through. LOS checks use Havok raycasts with `ENV_QUERY` so they ignore the player capsule.
- **Damage pipeline.** All damage goes through `Game.damageEnemy` -> `rollDamage` -> `EnemyManager.damage` (`applyDamage`: shields first, energy +50% vs shields). Feedback (hitmarker, numbers, sounds) is emitted from there. Future triggered effects hook in here.
- **Stats.** `Game.modifiers: StatModifier[]` -> `computeStats` -> `Game.stats`, read by weapon, turrets and movement. Loot and run upgrades should only add modifiers.
- **Gameplay vs visuals.** Effects are pooled and capped (`Effects.particleBudget`); logic never depends on them.
- **Rendering.** Surfaces are `PBRMaterial` (`usePhysicalLightFalloff = false`, so light intensities/ranges behave like the old StandardMaterial setup). Every glow/beam/additive sprite uses `unlit()` (PBR unlit = colour x texture, unclamped HDR). Do NOT use StandardMaterial for tinted or HDR glows: it adds emissive textures and clamps to 1.
- **Environment.** `Atmosphere.captureEnvironment` renders the static scene once (after `executeWhenReady`) into a ReflectionProbe, wraps the cube in a plain `BaseTexture`, prefilters it with `HDRFiltering`, and sets `scene.environmentTexture`. Never reference the probe's RTT from a material (it would re-render while sampled: GL feedback loop). DynamicTexture `clone()` yields a blank texture: build a second texture from the canvas instead.
- **Screen-space passes** (SSAO/SSR) use a separate geometry buffer (`forceGeometryBuffer`), not the prepass MRT, because prepass breaks particle rendering. Sprite-sheet particle systems also rendered incorrectly; use single sprites with random rotation.
- **Explosions** go through `Effects.explode(pos, {scale, debris, color})`: star flash, additive fireball, stretched sparks, embers, rising smoke, ground + air shockwave rings, smoke-trailing debris, flash light, scorch decal and a camera-shake request (`onShake` -> `Player.addTrauma` + lens kick). Shots on level geometry use `Effects.impact` (sparks, dust puff, burn decal).
- **UI.** Game publishes a HUD snapshot to `hudStore` at 20 Hz; instant feedback goes through `uiEvents`. Damage numbers animate imperatively (no per-frame React renders).
- **Data-driven content** in `src/data/defs.ts` (weapon, enemies, tower, economy).

## Known limitations / follow-ups

- Real-GPU frame rate not measured in this environment; use F3 on target hardware.
- Babylon is imported from the barrel (`@babylonjs/core`), so the bundle is large. Switching to deep imports would cut startup size.
- Turrets cannot be damaged and have no upgrades; core income outpaces spending in later waves (needs sinks later).
- Legendary signature effects are not implemented; no elemental damage types exist (Arc Conductor arcs are energy damage).
- Economy balance is first-pass (prices/costs in `economy/config.ts`, recipes in `economy/recipes.ts`). Item names are not regenerated after affix rerolls. Attachments are not swappable.
- Only the weapon has sockets; armor/shield/etc. sockets were never functional and were removed in save v3.
- The HQ preview has its own WebGL context while a terminal is open (released on close).
- Dropped weapons use the shared rifle hologram (no per-family world model).
- Balance is first-pass: enemy HP grows quadratically with waves while item power grows roughly linearly + affixes, so very deep endless runs still get harder. Drop rates/weights are in `drops.ts`/`rarity.ts`.
- Transitions wait for `whenReadyAsync` (cap 8 s); real-GPU transition time is unmeasured. The arena scene sometimes reports not-ready again after the first resolve (render targets); harmless.
- Closing a terminal with Esc cannot re-acquire pointer lock (browser rule): the pause overlay asks for a click. E closes and re-locks.
- Graphics quality applies immediately in the HQ (rebuild), on the next scene in the arena.
- Run suspension/resume is out of scope: closing the tab mid-run records it as `interrupted` (secured salvage kept, unsecured lost).
- High preset cost (SSR + SSAO + MSAA + 8 lights on PBR) is unmeasured on real GPUs; `Performance` preset drops SSR/SSAO/shadows/MSAA. Profile with F3.
- Enemies do not attack turrets; walkers only target the reactor and shoot the player.
- Gate frame pillars near the openings are visual only (no collider).
- No run upgrades, bosses, music, or multiplayer yet (by design).
