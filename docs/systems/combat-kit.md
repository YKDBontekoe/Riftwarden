# Combat kit (done, after the Game.ts refactor)

> Moved verbatim from the old root `CLAUDE.md` (2026-11). Quoted section names (e.g. "Loot depth", "Run map") refer to other files in this folder (index: [README.md](README.md)). Test counts are the numbers recorded when the work landed, not current totals.

- **Two weapons** (`arena/WeaponSlots.ts`): slot `weapon2` (SECONDARY WEAPON, optional, accepts weapons). One `Weapon` viewmodel stays; a swap rebuilds stats and calls `Weapon.setItem(item, def, false, quick)`, which keeps up to two built models (look key -> rig + animator) so swapping never rebuilds geometry, and a quick swap is ready after ~70 ms. Heat is per weapon: the holstered one is parked (`Weapon.heatState/restoreHeat`) and vents at full rate with no delay (`coolHolstered`). **Only the weapon in hand feeds the stat block** (`RunInventory.equippedItems(except)`, `Game.rebuildStats`, `ServerGame.rebuildStats` per avatar), and the signature is the one in hand. Keys: `Z` swap (rebindable action `swap`), `1` primary (also leaves build mode); swapping is refused in build mode. HUD: holstered row in the weapon card (`hud.holster`).
- **Slot defaults** (`defaultSlot`): an unqualified weapon equip replaces the primary; the secondary is always chosen explicitly (inventory TARGET SLOT picker, HQ slot). Other categories fill the first empty slot. Sanitize promotes a secondary to primary when the primary is missing.
- **Scoring** (`loadoutScore`): firepower = the better weapon (each with its own stat block); other headlines use the primary; `swapped` keeps slot order. Drone configuration shows a SECONDARY block.
- **Save v9** (`MIGRATIONS[8]`: `loadout.weapon2` + preset slots), PostgreSQL `003_secondary_weapon.sql` (slot check + preset column). **Protocol v8**: act `swap {slot}` (server validates the slot holds a weapon; claims are checked against the avatar's active weapon family); the client predicts the swap and reverts if refused. `scripts/bot.mjs` speaks v8.
- **Tests**: `tests/weapon-slots.test.ts`; `node scripts/e2e-combat.cjs` (A 8/8); coop protocol 49/49 (F4/F5 swap). Local PostgreSQL for the DB suites: initdb a throwaway cluster as the `postgres` user (e.g. under /var/lib/postgresql) on port 55432 and set `RIFT_TEST_DATABASE_URL=postgres://rift@127.0.0.1:55432/rift_test`.
- **Regression**: npm test 397 (with DB), m1 69/70 (known Z), m2 52/54 (known C8/C9), m3 37/37, m4 39/39, m5 24/24, m10 24/24, polish A-C 16/16, coop protocol 49/49, e2e-combat 11/11.
- **Shoot-off parts** (`enemies/limbs.ts` rules [pure], `enemies/limbRuntime.ts`): walker frames (walker, bulwark, sapper, marksman) have three parts (`cannon`, `arm` = left blade arm, `head`; `WalkerRig.armL` is new). `EnemyManager.damage` assigns non-DoT hull damage to the nearest intact part node within its reach (`limbForHit`, distances divided by the rig scale) and the part comes off at 30/26/28% of max hull (`limbDamage`, never on the killing blow): `fx.shatter(node)` throws the part's own instances, sparks/smoke/debris/socket flash, the node is hidden until respawn (`restoreLimbs` in `spawn`). Effects: no cannon = no shots at the drone and x0.5 reactor damage; no head = blinded (no shots, marksmen cannot paint), x0.8 move, x1.15 damage taken. Player feedback: personal UI event `limb` -> orange hitmarker + label (`CANNON SHEARED · DISARMED`, ...). Co-op: the recorder's damage wrapper compares the mask and pushes `['el', id, mask]`; replicas detach the newly lost parts (protocol v8). Tests: `tests/limbs.test.ts`, e2e-combat B (real weapon at the cannon).
- **Abilities** (`abilities/defs.ts` [pure], `arena/Abilities.ts`): item categories `ability` (Frag Charge, Cryo Charge, Arc Pulse, Blink Drive, Aegis Cell) and `ultimate` (Orbital Lance, Overdrive Core); `BaseDef.ability` names the kind. Slots `ability`, `ability2`, `ultimate` (save v10, `MIGRATIONS[9]`, PostgreSQL `004_abilities.sql`). No extra persisted roll: strength = def power x `flatScale(level)` x rarity baseMult x `abilityPowerMult` (overdrive = duration, rarity only; blink fixed 10 m). New stats + affixes: `abilityPowerMult` (apower), `abilityCooldownMult` (acool), `abilityRadiusMult` (aradius), `ultChargeMult` (ucharge). Keys: RMB ability I (RMB still leaves build mode), F ability II (F still repairs the inspected tower on mazing arenas), T ultimate during combat (T opens the tower panel in prep). Ultimate charge: `Director.deal` calls `Game.chargeUltimate(dealt)` for non-tower, non-hazard damage (not the orbital lance itself); full at `ult >= 1` (`charge` x `flatScale(level)` damage). Thrown charges fly ballistically (Havok ENV ray per step, enemy proximity, 1.6 s fuse) and blast through `director.blast` (source `effect` / `ability:<kind>`); Arc Pulse shocks + extra shield damage; Blink sets the controller position (clamped short of walls); Aegis/Overdrive are director buffs (shield capacity + resist / fire rate + move) and overdrive zeroes weapon heat. HUD: `AbilityBar` above the weapon card (`hud.abilities`). Drops/market/fabrication include both categories.
- **Abilities in co-op** (protocol v9): act `ability {slot, o, d}`; each `Avatar` owns an `Abilities` swapped in by `as()`, so damage charges the shooter's ultimate; blink moves the server body and sends `mv`; `me.ult` mirrors the charge; the client `mirrorUse`s cooldowns on an accepted reply. Limitations: director buffs are team-wide, so Aegis/Overdrive buff the whole team; the thrown charge mesh and the orbital beam are not replicated (the blast is); the "READY" alert is broadcast.
- **Tests**: `tests/abilities.test.ts` (defs/bases consistency, scaling, ult charge, blink clamp, v9->v10, runtime with fakes); e2e-combat C (frag via RMB, HUD rows, blink via F, orbital via T in combat); coop protocol F6. Regression after abilities: npm test 405 (+DB), e2e-combat 15/15, coop protocol 50/50, m1 69/70 (known Z), m2 52/54 (known C8/C9; B1 now expects 9 categories, C7 measures on the open south lane; I4 hits the same intermittent SwiftShader compile error as m1 Z), m3 37/37, m4 39/39, m5 24/24.
- **Movement kit** (`player/movement.ts` rules [pure], `player/MoveKit.ts` state machine, `arena/Movement.ts`): arena only (`MOVE.advanced`; `HQ_MOVE` has it off). States `'' | slide | wall | grapple | pound`; while one is active `MoveKit.velocity/vertical` own the velocity and `Player` skips its regular step. **Slide**: L-Ctrl (action `slide`) on the ground at >= 9 m/s: kicks to 26 m/s, friction 8 m/s^2, pulled down ramps by the ground normal, gentle steering, ends on release / airborne / < 8 m/s / 1.3 s (cooldown 0.45 s); eye dip 0.58; jumping out keeps the momentum. **Ground pound**: L-Ctrl after 0.18 s airborne: 44 m/s straight down (keeps 20% horizontal), on landing `kit.landed` -> `Game.groundPound(at, fall)` -> `Movement.blast`: `director.blast` (source `effect` / `move:pound`, charges the ultimate), radius 4.5 + 0.28/m (max 9.5), damage (70 + 9/m, max 260) x `abilityPowerMult` x `attackerScale`, shock from falls >= 6 m; cooldown 2.4 s. **Wall-run**: airborne >= 0.08 s, pushing a direction, >= 9 m/s along a vertical wall (Havok probes left/right of the view, reach radius + 0.5): runs at >= 21 m/s for up to 1.6 s with light gravity (0.16 -> ~0.5), refreshes the air boost, camera leans away from the wall; jump = wall jump (11 out, 10.8 up); the same wall is locked for 0.5 s; Ctrl drops off. **Grapple**: R (action `grapple`, free unless a tower is inspected: R still levels it) or middle mouse: Havok ray 46 m from the eye; hooks 0.6 m off the surface, pulls 82 m/s^2 (+9 lift) capped at 38 m/s, swing damped (no orbiting), releases at 3 m / 2.2 s / snag; jump releases with a hop; cooldown 4.5 s (miss 0.6 s, alert NO GRAPPLE POINT). Line = one unlit cylinder (`grappleLine`). Dash cancels slide/wall/grapple. **Containment**: grapple and wall-jump chains can clear the 9 m perimeter walls, so `ArenaBuilder.buildContainment` adds an invisible ring (y 8-90 over the perimeter wall footprint) in its own Havok group `PHYS_BOUND` (filter set on each child box: a container's filter alone did not stop ENV_QUERY rays), so it blocks the drone but LOS / grapple / loot rays pass through it. HUD: `hud.moves` -> grapple/pound chips + SLIDE/WALL-RUN tag in the player panel. Controls legend lists all four. `Flow` asks before unloading during a run (`beforeunload`; Ctrl+W cannot be intercepted outside fullscreen keyboard lock; off with `?test`).
- **Movement in co-op** (protocol v10): movement is client-predicted (speeds stay under `MAX_SPEED`); act `pound {p, f}`: the server checks alive, cooldown (x0.8 slack), position within 4 m of the avatar and clamps the fall to 20 m, then runs `Movement.blast` inside `as(a)`; its fx replicate. Not replicated: other wardens' grapple lines, slide/wall poses.
- **Tests**: `tests/movement.test.ts` (rules + MoveKit on a fake body: slide/pound/wall-run/wall-jump/grapple/miss/release); e2e-combat D (D1 slide, D2 pound kills a walker, D3 grapple to the north wall, D4 wall-run + wall jump, D5 HUD chips, D6 containment); coop protocol F7. Regression after movement: npm test 425, e2e-combat 21/21, coop protocol 51/51, m1 69/70 (known Z).
- **TTK pass** (`combat/heat.ts` `DAMAGE_PACE` = 1.9): player weapon damage tempo applied at fire time (`Weapon` shot + beam, `weaponSummary`, `ServerGame` claims, `Director.weaponBase`), so stored rolls stay; towers unaffected (FPS first). Starter repeater kills a walker in 3 bolts / 0.25 s (`tests/pace-feel.test.ts`, e2e-combat E1). A part comes off after ~1 bolt on it.
- **Hit feedback**: `Sfx` hit/crit/kill layered with low thumps, metal ring (crit) and a crunch + part rattle (kill). Kill flash: `PlayerCombat.kill` adds a star + short white light at the wreck; `KillPulse` HUD (screen-edge warm pulse on personal `hit:kill`, off with `prefers-reduced-motion`). Oil: burst kind `oil` (dark droplets, smoke-texture path) on every hit assigned to a part and a big spray on detach. **Legs**: fourth part `leg` (right `thighR`, share 32%, reach 0.7): x0.45 move (`LIMB_EFFECT.leglessSpeed`), `WalkerMotion.crawl` lowers hips 0.62, pitches the torso forward and leans it (`coreBehaviors` sets it each frame); label `LEG SHOT OFF · CRAWLING`. Lost-part masks still ride `el` (bit 8).
- **Wheel swap**: `Input.wheel` (notches per frame, trackpad deltas accumulated, only while locked; `simulateWheel`) swaps weapons outside build mode.
- **Deployables** (`abilities/defs.ts` kinds `wall`, `decoy`, `sentry`, `DEPLOY`, `deployPower`, `deployDistance`; bases `shield_wall`, `holo_decoy`, `mini_sentry`; runtime `arena/Deployables.ts`, one per Game, used by every avatar's `Abilities` via `AbilityHost.deployables`). Placement: up to 16 m along the aim, 0.8 m short of geometry, dropped to the ground. **Shield Wall** (14 s cd): 6 m x 3.4 m field for 6 s x rarity x sqrt(power): a static Havok box in `PHYS_ENV`, so enemy bolts (`updateProjectiles` ENV ray) and enemy LOS stop at it, while player hitscan (mesh picks on `surface`) passes; translucent fill + emitter rails, flickers in the last second. **Holo Decoy** (15 s cd): a hidden spare `Player` body + warden drone rig for 7 s with hit points (level-scaled); `EnemyContext.focus` (Game default, ServerGame after picking the avatar) points every enemy within 24 m at it; `ctx.hurtPlayer` now passes `enemyCtx.player`, and `Game.hurtPlayer` / the projectile loop (`decoyHitBy`) route hits to `hurtDecoy`. **Mini-Sentry** (20 s cd): `turrets.add` with `Turret.temporary` (free, `blocking` false, not inspectable, server refuses recycle/repair/modify) removed after 12 s x rarity x sqrt(power).
- **Ability modifiers**: run upgrades `a_payload` (+20% ability power), `a_cycle` (-15% cooldowns), `a_uplink` (+30% ult charge, +10% radius), gated by `needs.abilities` (`OfferContext.abilities` = equipped ability slots; co-op team offers pass undefined = eligible). Skill tree Vector branch templates `abilityPowerMult`, `abilityCooldownMult`, `ultChargeMult` (note: adding templates changes which stats existing profiles' unallocated/allocated nodes roll; allocations stay valid by id).
- **Abilities in co-op, fixed**: Aegis / Overdrive buffs carry `owner` (`Director.addBuff(..., owner)`, `buffModifiers(null)` = team, `buffModifiers(id)` = personal), so they only buff the caster. ULTIMATE READY uses the personal UI event `notice` (alert feed shows `alert` + `notice`). Thrown charges are drawn by `fx.thrown` / `fx.thrownEnd` (replicated FX_CALLS); the orbital beam adds a replicated `fx.tracer`. Deployables replicate as `['dp', kind, at, yaw, seconds, size]` (size = wall half-width / decoy radius / sentry tower id; clients build the wall with its collider, a visual-only decoy, and mark the `T+` tower temporary; the server sends `T-` on expiry).
