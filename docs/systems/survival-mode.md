# Survival mode + node intel (after the run map)

> Moved verbatim from the old root `CLAUDE.md` (2026-11). Quoted section names (e.g. "Loot depth", "Run map") refer to other files in this folder (index: [README.md](README.md)). Test counts are the numbers recorded when the work landed, not current totals.

- **Survival** (`ArenaConfig.mode` = `'defense' | 'survival'`, `RunMode` in `runmap/defs.ts`): no reactor to defend, no towers, every machine hunts the drone, **one life** (solo: losing the drone = defeat; co-op: a downed warden is out until the team secures the node and is revived by travel; the last one down = team defeat). Chosen with the deploy terminal switch (`flow.runMode`, `deploy(tier, entry, mode)`) for solo map runs, and by the lobby host (`{t:'mode'}`, `LobbyState.mode`, `Room.setMode`, `RunStart.mode`) in co-op. `MODE_EFFECT.survival` (budget x0.8, income +25%, loot luck +20%) is folded into every segment tier.
- **Hunt** (`arena/Hunt.ts`): the enemy context gets `Hunt.layout`, a prototype view of the real layout whose `reactor` is a point moved to the hunted drone by the focus hook before each enemy updates (`Game` enemyCtx.focus, `ServerGame.focus` per avatar). So walkers shoot it, rushers detonate on it, artillery ranges it, crawlers drill it and bosses beam it with no behaviour changes; `Game.damageReactor` turns those hits into `hurtPlayer(Hunt.hitFor(...))` on the focused drone (x0.8, max 40% of hull per hit); `hostileBlast` drops the reactor share. Survival always builds an `EnemyNavigator` (also on the classic arena) on the hunt layout; `NavGrid.retarget(goals)` seeds the field around the living drones (`HUNT_RADIUS` 3.5 m; a drone on a solid block seeds the nearest walkable ground, `walkableNear`) instead of the reactor ring; `Hunt.update` re-seeds when a drone moved > 3 m (at most every 0.8 s); every agent re-plans through the version bump. `EnemyManager.huntRange` (9 m): a machine that reached its goal (state `attack`) and lost the drone goes back to the chase (`pursue`). Tower building, the tower panel and `place` acts are refused; forge calibration and reactor repair are off; rest "repair" heals the drone. HUD: `hud.mode`, top bar "SURVIVAL · HUNTED · ONE LIFE" with hull instead of the reactor, no BUILD chip, survival hints, "DRONE LOST" panel.
- **Records**: `activeRun.mode`, `RunResult.mode` (`RunLedger.survivalMode`), history `mode`, `TierRecord.survivalRuns/survivalBestWave/survivalBestNodes` (tier unlocks and other records stay shared); PostgreSQL `008_survival_mode.sql`.
- **Node intel** (`runmap/intel.ts`, `RunMapScreen` tabs INTEL / REWARDS / ROUTE): `nodeIntel` runs a `SurvivalPlanner` with the arena's seed (`RunMapView.plannerSeed` = `Game.planner.seed`), the node's segment tier (node + act + mode effects) and faction, so the roster is what the node will actually compose (equivalence test); threat 1-5 = seconds of sustained fire per wave at the loadout DPS (`Game.firepower()` = `loadoutScore(...).dps`, gear only); rewards: wave/checkpoint credits, salvage, components, cores, caches, shards, boss/act loot, income/luck/drop deltas; hubs list stock and prices, forge prices, vault cache, anomaly choices. `lookahead` highlights every node the inspected one leads to (`MapChart` `ahead` dims the rest), rows to the boss, min-max fights (= waves), merchant/forge and rest availability. Hovering any node of the act inspects it; travel still uses the selected lit node.
- **Fixed in passing**: co-op never detected warden deaths (it compared alive state only around `tickVitals`, deaths happen in enemy updates/acts): `Avatar.wasAlive` now carries the previous tick (death count + DOWN alert); co-op hub nodes never opened the map vote and team statistics reset per node (each `ServerGame` started a fresh `TeamLedger`): `CoopSim.travel` restores the team ledger counters and hub votes no longer need the checkpoint flag.
- **Tests**: `tests/survival-intel.test.ts` (7: intel = planner roster, elite/boss/survival/hub intel, lookahead, hunt layout + hit cap, retargeted field leads to the drone, drone on a block, survival records); e2e-runmap B5-B8 (intel, lookahead, rewards, route) + S1-S5 (survival deploy, no build, paths to the drone, reactor untouched + drone hit, one-life defeat) 50/50; e2e-coop-map V1-V6 (host-only mode, runStart mode, towers refused, downed warden out, team defeat, PostgreSQL mode) 22/22. Regression: npm test 486 (with DB), coop protocol 51/51, e2e-combat 37/37, lint unchanged (6 warnings), build OK. A probe on a generated mazing arena: paths end 3-5 m from the drone, slowest sim frame 13 ms (SwiftShader).
- **Not done yet**: survival balance is first-pass (no player-damage scaling per behaviour; bosses' reactor attacks are capped at 40% hull); enemies do not split between wardens in co-op beyond "nearest living"; the deploy terminal remembers the mode only for the session; classic (non-map) survival is reachable only through `deploy(..., 'survival')`; intel ignores run upgrades in the DPS figure.
