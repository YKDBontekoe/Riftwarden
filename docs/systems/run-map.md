# Run map (Roadmap step 4)

> Moved verbatim from the old root `CLAUDE.md` (2026-11). Quoted section names (e.g. "Loot depth", "Run map") refer to other files in this folder (index: [README.md](README.md)). Test counts are the numbers recorded when the work landed, not current totals.

- **Structure** (`runmap/map.ts`): a run = endless acts, each `generateAct(mapSeed, act)` (memoised, pure, never stored): 7 rows; row 0 = 2-3 combat entry sectors, rows 1-4 = 2-4 weighted nodes (combat 44, elite 14 from row 2, event 14, merchant 8, vault 7, forge 6, rest 5 from row 3, one mid-act boss from row 3), row 5 = camp (always a rest + merchant/forge), row 6 = the act boss. Rows link by a monotone **staircase** (every node linked, no crossings). Every middle row offers a fight. Node `seed` = its sector's arena seed (biome/faction/name), `boss` alternates (`ACT_BOSSES`), `anomaly` on events. `mapSeedFor(hashRunSeed(runId))` (own stream); `reachable(seed, current)` = links, the next act's entry row after an act boss, act 1's entry row before the first node.
- **Combat nodes play a 5-wave segment with the global wave count** (node entered after wave W plays W+1..W+5, so `isCheckpointWave` banking, bosses, unlocks, records, XP and loot levels keep working). Hubs play no waves. `Game.cfg.node` (`NodeSetup`) -> `RunNode`; the segment's **effective tier** is `segmentTier(tier, nodeEffect(node, actEffects(carry)))` (hp/damage/speed/elite/budget/loot luck/income folded into the tier, id kept), so planner, spawns, loot and income need no map code. `SurvivalPlanner.setSegment` switches to **map mode**: bosses only where a node puts them (last wave of boss nodes), node events forced on the segment's middle wave, wave-clear cores x node `cores`. `WaveManager.hold` freezes preparation (hubs, a secured node).
- **Node modifiers** (`NODE_MODS`, combat kinds only, more with row/act; never on act 1 row 0): Elite Surge, Fortified, Blitz, Null Field (no towers: `setBuildMode` refuses), Bounty, Swarm Front / High-Value Target (forced event), Scarcity. Act effect (`actEffect`): every act after the first +8% hostile HP, +5% damage, +10% loot luck. Kind effects: elite x2.4 elites, x1.1 budget, x1.4 luck, +2 shards + elite cache; boss +1 shard; act boss +3 shards, act chest (2 elite caches, one epic floor), lifts curses and blessings (`endAct`), `actsCleared`.
- **Carry** (`RunCarry`): wave, cores (+ `towerRefund` = 50% of paid, wrecks 25% of that), reactor HP, ultimate charge, run build (stacks/picks/offers restored into `Director.build`, effects rebuilt), run loadout (uids; `RunInventory.adoptLoadout`), curses, blessings, forge stacks, run-only tower tech, owed upgrade picks, loot counter, damage dealt (statistics continue). The `RunLedger` is the same object across nodes (kills, waves, survival stats, secured items). Each node rolls its own loot/shard streams (`hashSeed(run) ^ node.seed`). Towers never carry (new arena).
- **Node end**: `RunNode.waveCleared(to)` -> complete, `mapDue`, hold, rewards, exit rift appears; the normal checkpoint bank already ran; the next prep opens the upgrade, then `openCheckpoint` opens screen `runmap` (not the checkpoint panel). H reopens it; BACK TO THE ARENA lets the player collect loot first (the map warns about drops left behind). **Travel** (`Flow.travel`): `MapSession.leave` banks what the ledger still holds (`RunLedger.bankNode` + `bankNodeRewards`, guarded by `activeRun.nodeBank` step), counts the node, stores the resume point, builds the next node's Game. **Extract** (`returnHome`) banks leftovers the same way.
- **Hubs** (`RunNode` stations, `visuals/nodeProps.ts`, ring of 11 m around the reactor facing the drop point, plus an exit rift; E at a station opens screen `station`, `StationScreen` calls `node.act(id)`): Merchant (3 seeded items, one rare+, priced in cores x `priceScale(wave)`; services: reactor repair, upgrade cache (owed pick), curse purge; items land in cargo, bank on leaving), Forge (run-only stat stacks: temper/plating/coolant/calibrate, +35% price per stack, max 4), Rest (one of repair + tactical refill / free upgrade pick / purge), Anomaly (6 kinds, `resolveAnomaly`: honest odds, seeded per node: curses, blessings, gambles, shards, items, ambushes), Vault (crack the seal -> guardian wave from the held wave's spawns at x1.25 HP; they go for the reactor; cache + 2 shards + credits on clear; blocks extraction while active).
- **Curses / blessings** last for the act (max 4 curses): stat curses via `carryStats` in `rebuildStats`, effect curses (famine, hunted, overclock) via the segment tier. Blessings: resonance, aegis, fortune.
- **Persistence**: `activeRun.map` (`RunMapState`: seed, act, current, path, cleared, actsCleared, resume `carry` + `next` + ledger counters), `activeRun.nodeBank`; optional fields, no save version bump (sanitize validates them). **Resume**: a run closed after a completed node is kept on load (`resolveInterruptedRun(..., {keepResumable})` in `Profile` only); the deploy terminal shows RESUME / END OPERATION (HQ terminals stay locked while it is suspended); `Flow.resumeRun` rebuilds a ledger from the stored counters (`RunLedger.restore`) and replays the chosen node with gear from the save. Records: `TierRecord.deepestAct/bestNodes/actsCleared`, `totals.nodesCleared/actsCleared`, history `act/nodes/path` (`pathCode`: "1C", "1E", "1B*"), result `RunResult.map`. PostgreSQL `007_run_map.sql` (`profileRows` reads NULL optional columns back as absent).
- **UI**: `RunMapScreen` (path, reachable nodes pulse, node card with sector/faction/waves/reward/risk/modifiers + affinity row, act effects, refund, left-behind warning, 1-4 + Enter), HUD `NodeChip` + station prompt, loading briefing node card (`TransitInfo.sector.node`), deploy terminal: act-1 preview with entry choice (`Flow.previewRunId` pins the next run id so the preview matches), records, map codex of recent paths, resume card. Controls legend updated.
- **Co-op** (protocol v11): `RunStart.node` (id, map seed, path, cleared, acts, carry with the player's loadout/ult). The server owns the node (`ServerGame` + `RunNode`), clients run `RunNode` in **replica** mode (stations, panels, prompts; `act` -> `station` act; state from snapshot `nd`). Snapshot `mv` = map vote; event `['vote', 2]` opens it (combat nodes: at completion, 60 s; hubs: from the start, 45 s after the first vote). `resolveMapVote`: majority, ties to the host's vote, `home` voters extract alone (their run ends `returned` with the path so far), everybody home = team extract; timeout without votes continues to the first node. `CoopSim.travel` banks leftovers per player, exports the team carry, disposes the ServerGame and builds the next one (same ledgers, deploy-time gear + restored run loadout/ult per avatar), then sends every replica a new `runStart`. Test servers keep the classic flow unless `RIFT_MAP=1`; production defaults to the map (`RIFT_MAP=0` disables). Online runs do not resume.
- **Testing**: `?test` keeps the classic endless flow (legacy suites); `?test&map` opts in, `?endless` turns the map off for players. `tests/runmap.test.ts` (21: generation shape/determinism/reachability/no crossings, effects, carry/refund/curses/sanitize, merchant/forge/anomaly odds, persistence + resume + records, ledger bankNode/restore, map vote rules); `tests/postgres-profiles.test.ts` round-trips map state + path. `node scripts/e2e-runmap.cjs` 41/41; `node --import tsx scripts/e2e-coop-map.mjs` 16/16 (needs `RIFT_TEST_DATABASE_URL`). Regression: npm test 479 (with DB), coop protocol 51/51, e2e-combat 37/37, m1 69/70 (known Z), lint unchanged (6 warnings), build OK. e2e-runmap filters the known SwiftShader hit-flash compile errors like m1 Z.
