## Loot depth, part 1 (M11, Roadmap step 3)

- **Drone Swarm family** (`swarm`; `SWARM_HIVE` in `data/defs.ts`, `FAMILIES.swarm`, bases `swarm_hive` / `swarm_brood` / `swarm_wasp`, barrels `sw_pod` / `sw_twin` / `sw_hive` (+1 drone) / `sw_uplink` (wider lock), mechanisms `mc_swarm` (`swarm`: launches while held) and `mc_salvo` (`salvo`: hold to lock like a charge, release: `salvoDrones(n, lock)` = 0.6x..3x the drones)). `WeaponDef.drones` / `seekCone` (tangent of the lock half-angle) are baked into the roll (`WeaponRoll.drones/seekCone`, `ComponentEffects.drones` additive, `seekCone` mult; sanitize + `006` columns). Each drone is one `ShotRequest` with `seek`/`seekIndex`: `traceShot` -> `seekLock` picks machines in the cone (angle minus body radius, in range, not hidden, Havok-free LOS pick against `surface` meshes), sorted by angle, drone i takes candidate `i % n`; no lock = the plain ray. Damage resolves at launch (hitscan rules); `WeaponFx.seeker` flies a curved bolt and plays the impact on arrival. Seekers never claim weakpoints and never pierce. Elements lean electric/corrosive. Co-op: no protocol change (claims are per drone, server `maxHits` 1 for swarm, fire budget x drones (x3 for salvo)); remote wardens' shots replay as seekers. Recipe `w_swarm`. Sound `swarmLaunch`.
- **Ascended** (rarity index 6, `weight: 0`, never rolled by weight): exotic numbers with baseMult 1.24 / affixMult 1.18 plus **one extra affix at the level's top tier with roll 1.0** (`generateItem` consumes its stream for it only on ascended items; `nameItem` prefixes "Ascended"), finish `ascended` (pearl shell, cyan trim), signature from the full non-unique pool, max enhance +18, pickups get a second counter-rotating halo + outer ring (`LootField`). Sources: (1) `rollDrops` promotes an exotic when `ascendDrop(seed, wave, tier)` (wave >= 15 or tier >= III, 1 in 10 by the drop seed: no extra random draw, so other rolls never shift); (2) the HQ: workshop ENHANCE tab -> ASCENSION (`ascendOwned` op `ascendItem`: rescales the exotic -> ascended multipliers, adds the perfect affix from `engineeringRand(item, 'ascend')`, so the preview equals the result; cost `ASCEND.shards/credits/components`). Uniques cannot ascend. Not trade-locked yet (no trading).
- **Rift shards** (`resources.shards`, `ResourceKey` 'shards', currency table entry, `res-sh`): banked like every resource (`Rewards.shards`, `RunResult.shardsSecured/Lost`, `TeamLedger`, ledger view `hu/hs`). Income (`RUN_INCOME`): elites `eliteShardChance(mods)` (own stream `Game.shardRand`, so loot rolls of a run seed are unchanged), bosses `bossShards(tier)`, elite assault / destroyed HVT events 2 (+1 tier IV+), checkpoints from tier III. Dismantling: exotic 1, ascended 5 (`SHARD_YIELD`). Older saves get 0 in sanitize (no version bump); PostgreSQL `profiles.shards`.
- **Hand-made uniques** (`loot/uniques.ts`, 15): fixed base, name, flavour, affix ids (rolled at the level's top tier, 70-100%), extra stats, `ItemInstance.uniqueId` (sanitize keeps it only on its own base; PostgreSQL `unique_id`). Weapons (7) carry a **unique-only signature** (`SignatureDef.unique`, never rolled) handled in `PlayerCombat` (`uniqueHitMult` for damage, `uniqueAfterHit` for procs): Heartbreaker (weakpoint +70% + corrode), Overseer's Gaze (every 8th tick chains), Rime Warden's Breath (+40% vs chilled, frozen kills shatter), Crucible Choir (burning targets ignite neighbours), Jury-Rig (hot arcs), Hive Mother (kills release seekers), Ninth Gate (pierce +2, +20% per pierce: mirrored in `ServerGame.shot`). Gear (6 with effects + 2 stat profiles): `CombatHost.uniques()` = `gearUniques(equipped except the holstered weapon)` (Game `gearEffects` rebuilt in `rebuildStats`; ServerGame per `Avatar.uniques`), effects Mantle (kill heals 4% hull), Logic Lattice (crits +1.5% ult), Tailwind (kill dash refund +50%), Frostbound Aegis (hits on chilled restore shield), Reactor Heart (+30% above 60% heat), Monocle (+35% beyond 30 m); Sapper's Last Fuse and Orbital Writ are stat-only. **Target farming**: `uniqueForDrop(source, seed, faction)` turns at most one drop per trigger into a unique when `uniqueChance(seed, id) < chance` (seed-decided, no stream shift); `RollParams.faction` = `Director.faction` (null on the classic arena, so faction uniques only drop in generated sectors). Boss uniques 6% per drop, faction uniques 3.5-5% from elites/caches/archetypes, Ninth Gate 12% per HVT drop. Affix engineering refuses uniques ("Unique affixes are fixed"); enhancement and component refits are allowed. Item card: UNIQUE tag, UNIQUE EFFECT block with flavour and sources (`uniqueSourceText`). Debug: `__rift.makeUnique(id, seed, level)`.
- **Fixed in passing**: a component refit (`swapComponent`) dropped the weapon's element (refitted elemental weapons became kinetic); it now keeps it.
- **Tests**: `tests/loot-depth.test.ts` (16: swarm generation/summary/salvo/elements/refit/sanitize/recipe, ascended weight/promotion/generation/ascension transaction/preview, shards ledger/banking/sanitize/dismantle, uniques validity/determinism/sanitize/target farming rates/mechanics/engineering block), `tests/loot-roll.test.ts` reference now includes the unique conversion, `tests/postgres-profiles.test.ts` round-trips shards, a unique swarm weapon and an ascended item. e2e-combat H (H1 seekers lock off-crosshair targets, H2 salvo 3 -> 9 drones, H3 Mantle heals on kill, H4 ascended pickup + swarm viewmodel screenshot).
- **Regression**: npm test 457 (with DB), e2e-combat 37/37 (incl. H), coop protocol 51/51, m4 39/39, m2 52/54 (C8/C9 known). Lint: same 6 warnings as before.

## Loot depth, part 2: Launcher + Flamer (M11)

- **Launcher** (`launcher`; `LAUNCHER` in `data/defs.ts`, bases `launcher_tube` / `launcher_siege` (heavy, elite damage) / `launcher_hornet` (light), barrels `ln_tube` / `ln_twin` / `ln_long` (guided: range, accuracy, smaller blast) / `ln_wide` (thermobaric: +35% blast), mechanisms `mc_rocket` (`rocket`, fires while held) and `mc_cluster` (`cluster`: main blast + three bomblets)). `WeaponDef.splash` = blast radius (`WeaponRoll.splash`, `ComponentEffects.splash`). A shot traces the hitscan ray; the impact is the first machine or surface (no impact in range = the rocket flies off). `PlayerCombat.launch` schedules the detonation with `director.later(distance / boltSpeed)`, so damage lands when the rocket arrives; `detonate`: full damage to a direct hit (alive, same spawn gen), a 75% blast with 55% falloff (element payload applies), cluster bomblets (3 x 30%, r 0.5x); machines killed by the blast count as mastery kills. Visual: `rocketFx` (bolt + smoke puffs + explosion styled by element + bomblets) on `WeaponFx.later` (presentation timer that runs on replicas too).
- **Flamer** (`flamer`; `FLAMER`, bases `flamer_torch` / `flamer_inferno` (heavy, elemental power) / `flamer_needle` (light, cooling), barrels `fl_nozzle` / `fl_fan` (+40% cone, +1 machine) / `fl_lance` (narrow, +30% range) / `fl_twin` (+15% damage, heat), mechanisms `mc_spray` (`spray`) and `mc_jet` (`jet`: half cone, -2 machines, +40% range, +35% damage)). `WeaponDef.spray` = cone tangent, `targets` = machines per tick. Ticks like a beam (`Weapon` case spray/jet, `beaming` drives the pilot glow); each tick `traceShot` with `cone` returns up to `targets` machines in the cone in sight of the eye (`coneCandidates`, shared with the swarm lock), every one takes the full tick. Never kinetic (`ALWAYS_ELEMENTAL`: the kinetic draw is still consumed so streams do not shift). Visual: `flameFx` bursts of the element (fire / frost / oil / zap / plasma) along the stream; sounds `rocketLaunch`, `flame` (`Sfx.heavyWeapon`).
- **Co-op**: no protocol change. Flamer claims carry up to `targets` hits (`maxHits`), each validated like any hit. Launcher claims: a claimed direct hit is validated, otherwise the server raycasts the impact along the claimed direction (`ordnanceCtx.ray`); `ServerGame.launchClaim` replicates `['shot', id, 'launcher', impact]` and schedules the detonation inside `as(a)` (dropped if the warden left; blast damage counts to `a.damage`). Remote replays: rocket + explosion / flame puffs (element not replicated: thermal look).
- **Progression**: unlock track `family:launcher` (Warden 9), `family:flamer` (Warden 11), loot locks, recipes `w_launcher` / `w_flamer`, mastery families with component ranks (cluster / jet at 5, thermobaric / fan at 10, prism at 20) and perks, codex entries, module families. Item card + comparison: blast radius, spray cone, machines per tick.
- **Tests**: `tests/heavy-weapons.test.ts` (6: generation/determinism/mechanisms per chassis, thermobaric + refit rescale, flamer cone/targets + never kinetic, jet/fan effects, sanitize clamps, recipes/mastery/unlock/compare rows); e2e-combat I (I1 rocket damage waits for the flight then splashes, I2 flamer reaches three machines in its cone and not one at 40 m, I3 viewmodel screenshots). Regression: npm test 598, e2e-combat 40/40, e2e-m3 through D (known stale H1), e2e-riftlevels E-F 16/16, lint unchanged (6 warnings). Co-op protocol suites not run (no database in this container).
- **Not done yet**: DPS readouts count the direct hit only (launcher) and one machine (flamer); no self-damage; rockets do not curve or track; the replicated rocket/flame look ignores the shooter's element; no dedicated uniques for the new families; real-GPU look and feel check.

## Loot depth, part 3: sets, conditional affixes, build-aware score (M11)

- **Sets** (`loot/sets.ts`): four sets (Bastion tank, Deadeye crit, Conflux elements, Architect towers), bonuses at 2 and 4 equipped pieces (distinct items). `ItemInstance.set` on rare+ armor/shield/reactor/processor/accessory, decided by `setFor(seed, rarity, category)` (hash, 20%, no generator stream draw: no other roll shifts); starter-grade (`fixedRoll`) kit and uniques never belong to a set; sanitize keeps a valid id on set gear only. Bonuses are stat modifiers appended by `equipmentModifiers` (`setBonusModifiers`), so Game, the co-op server (tower bonuses split 1/n like tower gear) and scoring all see them. UI: SET tag + `SetBlock` on the item card (bonuses, x/4 worn via `EquippedItemsContext` from InventoryView, "brings the set to n/4"), SETS row in drone configuration. JSON documents: no migration.
- **Conditional affixes** (`combat/conditions.ts`, affixes `c_airdmg` Skyborne, `c_dashrate` Slipstream, `c_swapdmg` Quickdraw, `c_lowresist` Last-Stand, `c_killmove` Bloodrush, `c_killcrit` Predator; weights 2-4, bigger numbers): `AffixDef.cond` -> `StatModifier.cond` (`itemModifiers`); `computeStats(mods, base, active)` skips conditional modifiers whose condition is not active. One `ConditionTracker` per drone: Game (`tickConditions` after `player.update`: dash edge, airborne = !grounded, hull; `swapWeapon` notes swaps, `masteryKill` notes kills) and the replica (kill from the personal `hit:kill` event); the server keeps `Avatar.conds` (airborne = input flag bit 32 sent by ClientGame, dash = flag 16, swap act, kill in `gainMastery`). Stats rebuild only when the active set changes and the loadout has conditional modifiers (`condMods`). Implicit stats block conditional variants of their stat too (`groupsOfStat`, also in ascension and rerolls). Item cards print the condition under the affix (`cond-tag`).
- **Build-aware score** (`loadoutScore(items, ctx)`, `swapImpact(..., ctx)`, `ScoreContext {extra, mastery, faction}`): conditional modifiers count at their expected uptime (`expectedModifiers`), set bonuses through the equipment block, `extra` = skill tree (+ run upgrades and node effects in the arena), mastery of the family in hand, and weapon DPS x elemental power (elemental weapons) x `affinity` against the sector faction. Arena: `Game.scoreContext()` feeds the pickup verdict (`LootVerdictHost.scoreContext`) and the cargo screen; HQ: `TerminalHost` provides `ScoreCtx` (tree + mastery from the save, no faction); `useScore` / every `swapImpact` call in the terminals reads it.
- **Tests**: `tests/sets.test.ts` (4), `tests/conditions.test.ts` (4), `tests/build-score.test.ts` (4: crit tree flips a verdict, faction affinity, conditional uptime + set completion, mastery); e2e-combat J (J1 airborne damage affix only while airborne, J2 dash window). Regression: npm test 610, e2e-combat J 3/3, e2e-m4 39/39, e2e-riftlevels G 4/4, lint unchanged (6 warnings).
- **Follow-ups (done)**: `statTotals` keys by (stat, op, cond), so the comparison table keeps conditional affixes on their own rows labelled with the condition; HUD `conds` (`condIdsOf` / `condHud`, `Game.condIds`) -> `CondRow` chips under the drone panel (AIRBORNE / DASH / SWAP / LAST STAND / KILL, lit while active; only with conditional gear); **set target farming**: `SET_SOURCES` (bastion: bulwark/enforcer/crawler/burrower/colossus, deadeye: marksman/artillery/skimmer/hvt, conflux: elite/eliteCache/jammer/overseer, architect: engineer/sapper/checkpoint) raise the set chance to `SET_FARM_CHANCE` 40% with the favoured set `SET_FARM_BIAS` 70% of the time (`setFor(seed, rarity, category, source)`, `GenSpec.dropSource` from `rollLoot`; other sources roll exactly as before), the item card lists the sources; set pickups get a teal hexagon of ground ticks (`LootField` `lootSetGlow`) and the pickup prompt a `SET · NAME · n/4 IF EQUIPPED` line (`LootTargetInfo.set/setPieces`). Pack DPS: `weaponSummary().packDps` = dps x `packFactor` (3 grouped machines: launcher blast + cluster, flamer targets, rail pierce) on item cards, comparisons and drone stats; `dps` stays single-target (scores, intel). Tests in `tests/{conditions,sets,heavy-weapons}.test.ts`, e2e-combat J3 (chips) / J4 (set pickup).
